# 실제 제품 검증 실행안

원본 [제품 가설·계측](../postpone-app-docs/11_PRODUCT_VALIDATION.md)의 H-01~07과 [전체 구현 계획](IMPLEMENTATION_PLAN.md)의 G-UX를 실행 가능한 과제로 연결한다. 이 문서는 연구 실행이나 참여 동의가 확보됐다는 증거가 아니다.

## 실행 전 조건

최신 commit의 필수 Actions 빌드·저장·UI 검증과 G-WIDGET/G-SYNC의 대상 기능 검증을 확인한다. 동의한 참여자와 기기를 준비하고 목적·녹화 여부·요약 공유·철회/삭제 방법을 설명한다. 원본의 5~8명, 이후 1~2주 관찰은 권고안이다. 모집·녹화·외부 전송을 코드 제작 승인으로 대신하지 않는다. 진단·치료 효과를 평가하거나 참여자의 진단을 추정하지 않는다.

과제에는 실제 개인 작업 대신 참여자가 선택한 비민감 제목 또는 제공한 예시를 사용한다. 관찰자가 입력 원문·iCloud 계정·기기 식별자를 검증 기록에 복사하지 않는다. 실패를 숨기거나 3분에 강제로 종료하지 않는다.

## 과제와 판단

| 과제 | 관찰과 기대 | 연결 |
|---|---|---|
| 제목만으로 작업 입력, 공백/긴 원문 오류에서 회복 | 필수 분류 없음, 원문 자동 잘림 없음, 다시 찾을 수 있음 | H-01, Q-001~004/007 |
| 미래 날짜에 3개, 다음 주의 금요일에 1개 배치 | Today에 자동 포함되지 않고 날짜 전 자동 재질문 없음; 검색에서는 조회 | H-02/03, Q-008~018 |
| 다음 주의 요일은 나중에 선택 | 주만 지정의 의미를 설명할 수 있음; 월요일 확정 오해 없음 | H-04, Q-013/014/028 |
| 10개 중 6개 결정 후 중간 종료하고 같은 날 재방문 | 나머지 4개 보존, Today 자동 유입 없음, 명시 이어 정리 가능 | H-05/06, Q-019/022/023 |
| 마감 이후로 배치·취소·확인, 직전 결정 Undo | plan/deadline/완료 구별, 확인 전 변경 없음, 이전 계획 회복 | H-03/06, Q-025~031 |
| 동일 과제를 앱과 실제 홈 위젯에서 수행 | 대상 고정, 두 위젯/연속 탭에서 다른 작업 변경 0건, 지연과 숙고 분리 | H-07, G-WIDGET |
| 다음 날 재방문·미래 작업 검색·선택한 일 시작 여부 자기보고 | 자동 이월 없음, 재등장 신뢰 및 관리 후 행동을 자기보고로 확인 | H-02/05/06, Q-017/018 |

예시의 원본 개수·날짜를 바꾼 실험은 원본 QA의 전체 실행과 별도 사례로 기록한다. 앱 과제 통과를 실제 위젯·Siri·계정 동기화 과제의 통과로 확대하지 않는다.

## 계측의 정확한 범위

`LocalMetric`에는 종류·surface·결과·목적지 종류·개수 구간·처리 시간·앱 정리 능동 시간만 담을 수 있다. 제목·메모·구체 마감·taskID·계정 ID 필드는 없다. 로컬 기록은 14일 범위와 최대 1,000개로 제한하며 삭제할 수 있다. 공유는 설정에서 명시 동의한 요약 JSON export만 수행한다.

입력 시도는 흐름 시작에 한 번, 저장 성공은 원본 commit 결과에 기록한다. 검증/저장 거절과 committedProjectionPending을 구분하고 같은 receipt의 재시도는 저장 성공을 중복 집계하지 않는다. 앱 정리 능동 시간은 실제 정리 화면이 보이고 해당 scene이 active인 구간을 ContinuousClock으로 합산한다. Widget 인텐트의 처리 시간은 별도 값이며 능동 시간이나 숙고 시간으로 합산하지 않는다.

현재 요약 export는 이벤트 종류별 개수와 앱 능동 시간 합계다. 참여자별 원문, 주기별 의도 불일치·재등장 신뢰, 완료율의 원인, 일간 3분 이하 비율을 자동 산출하지 않는다. 특히 일부 흐름·surface가 계측되지 않았다면 이를 전체 입력 완료율로 해석하지 않는다. 주기별 측정 가능한 분모·0결정 종료·의도 일치와 사용자 숙고는 동의한 관찰 기록으로 보완한다. 첫/마지막 Widget 탭의 차이는 필요한 경우 observedInteractionSpan으로 별도 표기한다.

## 기록과 차단 기준

각 실행에 실제 commit/run, OS/기기/표면, 고정 또는 실제 계획 시간대, 권한/계정 조건, 과제·기대·관찰, 결과 pass/fail/blocked/not_run, 비민감 증거 링크를 남긴다. 참여 정보와 raw 영상은 승인된 위치·보존/삭제 범위에서 별도로 관리한다. 이 저장소에 개인 정보를 넣지 않는다.

입력 유실·다른 작업 변경·미검토 Today 유입·자동 마감 변경·계정 혼합·삭제 부활은 한 건이라도 출시를 차단한다. 실패 시 문구/목적지 의미, 반복 노출, 뒤로/Undo, 주 상태, 위젯 패널 순서로 수정한다. 클릭률이나 많이 미룬 횟수를 성공 지표로 삼지 않는다. 실제 결과를 [추적표](REQUIREMENTS_TRACEABILITY.md)에 남기기 전 G-UX는 not_run이다.
