# 전체 제작과 UI 수용 계획

2026-10-03의 사용자 목표는 전체 제품 제작이며, 심플한 입력·미루기와 플랫폼별 화면 분배를 끝까지 검증한다. 범위는 [전체 구현 계획](IMPLEMENTATION_PLAN.md)의 D-01~D-16, [요구사항 추적표](REQUIREMENTS_TRACEABILITY.md)의 FR 30개·NFR 12개·QA 87개·네 수용 게이트를 그대로 유지한다. 정지사진, 코드 작성, Simulator 검사, 실제 기기·계정·사용자 수용은 별도로 기록한다.

## UI 완료 기준

현재는 입력 owner·재시도/초안 보호와 실제 실패 화면 확보를 우선한다. 기본·다크의 기존 성공 이미지 계약을 유지하면서 Adaptive 실패의 현재 fixture 앱 이미지를 별도 진단으로 보존한다. 완료된 recordComplete·source·receipt·실패 native 종료 코드를 확보하지 못하면 진단도 게시하지 않는다. 새 소스의 SDK·회귀 결과를 확인한 뒤 실제 이미지에서 입력·미루기·큰 글자·좁은 창을 검토하고 다음 수정의 근거를 남긴다. 부분 빌드 성공이나 진단 artifact가 이 완료 기준을 충족한 것으로 취급하지 않는다.

- 기본 입력은 제목과 저장만 요구한다. 날짜·메모·링크를 펼치지 않아도 저장할 수 있고, 선택한 날짜를 입력 화면에서 함께 저장할 수 있다.
- 오늘·내일 미루기는 목록에서 쉽게 접근하며 완료·실제 마감을 바꾸지 않는다. 실제 마감 이후 배치는 확인하고 저장 결과 전에는 성공이나 다음 카드로 진행하지 않는다. 취소·stale·실패·Undo에서 표시한 작업을 유지한다.
- iPhone은 세 탭, iPad/Mac은 가용 폭에 맞는 탐색·본문·선택 상세를 사용한다. 선택하지 않은 상세와 불필요한 참고 열이 화면을 차지하지 않으며 큰 글자에서는 재배치한다. 키보드·탭·시스템 안전 영역이 저장·오류·되돌리기를 가리지 않는다.
- 글자 확대 때 필요한 문구를 잘라내지 않고 스크롤로 모든 핵심 행동에 도달할 수 있다. 버튼의 역할·이름·선택/접힘 상태가 실제 접근성 트리에 있고, 동작의 키보드 대체가 있다.
- 밝은·어두운 세 플랫폼, 최대 글자, 검증 가능한 좁은 창에서 새 소스의 검사와 원본을 직접 확인한다. 접근성 audit의 모든 실제 issue는 원인을 분류하고 제품 issue를 수정한다. 사전에 전체 audit를 무시하거나 테스트·timeout·성공 판정을 약화하지 않는다.
- 알려진 차단 문제가 없고 새 소스의 검사·시각 근거가 있어야 자동화 범위의 UI 수용으로 기록한다. 사진만으로 실제 터치·VoiceOver·Split View·두 기기 동작을 완료 처리하지 않는다.

## 외부 의존성과 완료 구분

실제 Apple 등록값과 새 프로파일, 물리 iPhone/iPad/Mac·두 계정/기기와 사용자 과제가 필요하다. 등록값·기기 접근이 없는 항목은 정확한 선행 조건으로 남기고 독립적인 구현·원격 검증을 계속한다. 실제 사용자 데이터 삭제·새 외부 서비스 등록·PR 병합은 기존 구현·배포 승인과 구분한다. 코드 구현 완료를 이 외부 수용 완료나 무조건적인 ‘완벽’ 판정으로 대신하지 않는다.

추가 API·UI 상태·원본 기록은 기존 도메인 불변식, 멱등성·조건부 Undo와 원본 보존을 유지한다. 계획한 생성은 새 기록 schema2로 명시하고 기존 날짜 없는 capture의 schema1·논리 digest를 보존한다. 구버전 클라이언트는 새 schema를 미지원 원본으로 보존·격리해야 하며, 새 기록을 기존 미배치 생성처럼 잘못 적용하면 안 된다.
