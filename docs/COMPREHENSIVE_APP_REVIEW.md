비교 기준 `95146d2`의 [기본 배포 검사 105](https://github.com/hellosunghyun/mirror/actions/runs/37171133307)는 SwiftPM과 세 플랫폼 앱·확장 빌드 및 단위 단계는 성공했지만 실제 UI 단계는 모두 실패했다. iPad는 일부 사례가 통과했고 전체 수용은 아니다. IPA·DMG 생성과 게시 단계는 건너뛰었다. 새 변경의 성공 근거로 이 이전 실행을 사용하지 않는다.

실패 로그와 이미지는 실행 SHA·attempt 및 artifact digest를 확인한 뒤 읽는다. XCTest query와 상세 이력 탐색의 알려진 오류만 고정 enum으로 요약한다. 원문 AX·제목·경로·값을 공개 공지로 전송하지 않으며 진단 정보는 통과 판정·assertion·시간 제한을 바꾸지 않는다. 추가 audit 콜백도 `.all`을 유지하고 항상 `false`를 반환해 어떤 issue도 무시하지 않는다.

`ecebd93`의 [Adaptive 실행](https://github.com/hellosunghyun/mirror/actions/runs/37193375345)에서 Mac system 앱과 runner 빌드는 성공했지만 네 사례가 첫 접근성 감사 호출에서, 계획 입력 사례가 추가 옵션 펼침 뒤 `capture.planToday`의 존재·고유성 검사에서 실패했다. 이후 복구한 실제 로그에서 입력 감사의 `Parent/Child mismatch`, 정리·검색·좁은 창 감사의 `Element has no description`을 확인했다. 구체적인 대상 요소는 아직 확정하지 않았으며 지원 불가나 앱 중단으로 단정하지 않는다. 전체 헤더 버튼은 조작 개선이며 실패 원인 확정이나 수용 통과를 뜻하지 않는다.

같은 실행의 Mac 실패 화면 4장과 iPhone dark 정리 화면 1장을 직접 확인했다. 정리를 시작한 화면에 이전 입력 안내와 Undo가 남고, 최대 글자 요청에도 정리 버튼이 일반 크기의 가로 배치를 사용하는 문제가 관측됐다. 루트 환경 검사만으로 별도 창의 최대 글자 수용을 보장할 수 없어 세션 표시와 창별 환경 전달·검사를 보강한다. 이 사진은 `ecebd93`의 실패 진단이며 후속 소스나 전체 흐름의 시각 수용은 아니다. iPad 화면은 아직 직접 확인하지 못했다.

## 전체 완료까지 남는 구현과 검증

일반 날짜 선택창에서 A 저장 뒤 화면 반영이 실패한 상태로 B를 고르면, 같은 토큰의 다른 내용이 거절되면서 원래 재확인 명령을 잃을 수 있었다. 실제 표시한 선택창·원래 작업과 날짜·승인·저장소의 소유를 고정하고, 불확실한 동안 새 날짜 제출 대신 같은 화면의 재확인을 제공한다. 원래 목표를 표시하고 작업명은 계속 펼쳐 읽을 수 있다. 이때 닫기는 저장 취소와 구분하며 닫힌 뒤에도 원래 명령을 재확인한다. 늦은 응답은 새 선택창이나 공간을 바꾸지 않고, 같은 살아 있는 저장소의 명시적 재시도만 관측을 다시 연결한다. 일괄 선택의 등록도 원래 ID·토큰·관측이 일치할 때만 함께 연결하며, 다른 명령의 투영 복구를 먼저 처리한다. 단일·일괄 저장 전후 장애, 다른 날짜 거절과 원본 1개, 마감 승인 보존, 닫힌 P·새 Q·관측 변경을 실제 Store에 연결한 회귀 네 개와 독립 정적 검토를 추가했다. 실제 Swift 컴파일·회귀 및 선택창 실패·재확인 UI는 다음 Actions에서 검증한다. FR-009/018/030, Q-015/053~060/071/075/080에 연결한다.

설정 화면의 공간 전환 가능 여부가 위젯의 미해결 요청을 직접 관측하도록 해당 저장 필드의 Observation 제외를 제거했다. 저장 중 표시나 확인창의 우연한 동시 갱신에 의존하지 않고 요청 해제 상태를 전달한다. 위젯 명령·소유권 계약은 유지하며 독립 정적 검토를 마쳤다. 늦은 취소 후 실제 SwiftUI 화면 갱신은 다음 앱 검증 대상이다.

일반 알림 설정도 OS 권한 대기 중 계정 격리·기기 초기화가 발생하면 옛 요청의 ON 선택을 새 공간에 기록할 수 있었다. 시작 시 저장소 관측과 서비스 actor를 보관하고, 각 await 및 예외 뒤 동일성을 확인한 다음에만 권한 상태·안내·설정 journal을 갱신한다. 권한 결과는 검증 전 지역 변수에 보관한다. 독립 정적 경로 검토를 마쳤고 실제 OS 권한 대기와 공간 변경의 수용은 별도로 남아 있다. FR-020/022/025/030, Q-061/074/081에 연결한다.

실제 마감 편집은 별도의 초안 소유권이 없어 다른 창의 목록 전환으로 닫힐 수 있었다. 표시 전에 기존 상세 편집 claim을 확보하고, 마감·알림 초안과 제출 상태를 같은 표시 요청에 묶는다. 변경한 초안에만 폐기 확인을 제공하고 저장 중 중복 제출·닫기를 막는다. 마감 저장과 알림 권한 결과는 분리하며 불확실한 저장은 원래 명령으로 재확인한다. 늦은 결과가 다른 편집·공간의 설정이나 표시를 변경하지 않도록 내부 명령 결과와 알림 권한 대기 뒤에도 같은 owner·마감 버전을 검사한다. 독립 정적 검토를 마쳤으며 실제 마감 UI·두 창·권한 거절·재시도 수용과 Swift 컴파일은 새 Actions에서 확인해야 한다. 전체 창별 탐색 분리를 완료한 변경은 아니다. FR-014/022/025/030, Q-025~028/071/075/079에 연결한다.

로컬 삭제 후 알림·검색 노출·캘린더 선택 OFF를 메모리에만 바꿔, 후처리나 새 저장소 열기가 실패하면 재시작 때 이전 ON 설정을 다시 읽는 호출 누락을 수정했다. 새 구성으로 바꾼 뒤 첫 후처리 await 전에 기존 설정 저장 경로로 defaults와 새 세대 journal을 보존한다. 이 시점의 services는 nil이므로 OS 후처리를 먼저 예약하지 않으며 구 공간 정리는 새 journal을 지우지 않는다. 기존 journal의 공간 격리·재시도 보호를 재사용하고 독립 정적 검토를 마쳤다. 실제 앱 삭제·후처리 실패·재시작 시나리오의 기기 검증은 별도로 남아 있다.

위젯에서 확정 거절된 날짜·카드가 재시도 상태에 남아 일반 미루기를 막고, 취소한 위젯 A의 마감 승인이 앱 B의 확인과 섞일 수 있는 경로를 수정했다. 실제 표시한 envelope·카드·목표·토큰·관측과 저장 공간을 함께 소유하며 자동 alert 해제 전후 어느 순서에서도 같은 확인만 소비한다. 자정·외부 변경·이미 결정됨·없는 작업은 해제하고, 저장 여부가 불확실하면 마감 승인까지 원래 명령에 보존한다. 명시적 재시도만 동일한 살아 있는 저장소 actor와 공간에 관측을 다시 연결하며, 미해결 위젯 요청 중 공간 전환을 막는다. 일반 앱 재시도 정책과 실제 Cloud 전환 본문은 유지한다. 실제 WidgetReviewService·MirrorStore 결과에 연결한 자정·stale·저장 전후 장애·원본 1개·동일 actor·A/B 확인 분리 회귀와 독립 정적 검토를 추가했다. 실제 Swift 컴파일·회귀·SwiftUI alert 순서는 다음 Actions 검증이 필요하다.

Cloud 연결을 중단하고 로컬 저장소를 다시 연 뒤에도 프로세스의 시스템 서비스 캐시는 중지된 옛 actor를 돌려줄 수 있었다. 명시적 `disable`이 새 로컬 저장소를 성공적으로 연 다음에만 해당 디렉터리의 캐시를 비운다. 일반 open에서 닫힌 writer를 자동 재개하지 않으며 기존 상태 전환 순서도 유지한다. 실제 suspend와 exportAndSuspend 두 경로에서 복귀 전의 닫힌 캐시·복귀 뒤 새 서비스·원본과 같은 명령 영수증·새 Shortcut 기록의 앱 조회를 검사한다. 독립 정적 검토를 마쳤고 회귀 실행은 다음 Actions에서 확인한다. 실제 Cloud 계정 연결 성공을 대신하는 검사가 아니다.

복원은 원본 append 뒤 계정 출처를 기록해 두 쓰기 사이 중단 때 출처가 사라질 수 있었다. 같은 저장 잠금에서 출처를 먼저 원자적으로 보존한 뒤 원본을 append하도록 바꿨다. 원본 저장이 실패하면 출처가 보수적으로 넓게 남을 수 있으나 다음 이관에 필요한 계정 동의를 생략하지 않는다. public import API는 유지하고 내부 장애 지점으로 원본 저장 전·후에 중단한 두 경우를 추가했다. 실제 SQLite 재개 후 원본 전체 행·export 출처·다른 로컬 공간의 동의 요구·동일 archive 및 명령 재시도 영수증을 검증한다. 독립 정적 검토를 마쳤으며 새 회귀의 Actions 실행은 남아 있다.

App Group 이전 경계를 읽는 중 기존 `MirrorStore.init`이 원본 재생 뒤 두 번째 잠금을 얻고도 저장 세대를 재검사하지 않는 경합을 확인했다. 최종 잠금 안에서 identity를 재검사하고 오류에도 잠금을 해제하도록 보완했다. 실제 suspend로 세대가 바뀌거나 전환 표식이 설정된 두 경우에서 낡은 초기화가 투영을 덮지 않고, 원본과 동일 명령 재시도를 보존하는 회귀를 추가했다. public initializer는 유지하며 결정적 경합 hook은 내부에 한정한다. 독립 정적 검토를 마쳤고 실제 Swift 컴파일·회귀는 다음 Actions에서 확인한다. 저장 위치나 App Group 활성화 변경은 아니다.

- App Group·iCloud Container의 실제 Apple 등록과 서명 entitlement 연결이 필요하다. 현재 빈 설정을 임시 경로의 성공으로 대체하지 않는다. 위젯·공유 확장·실제 두 기기 동기화의 수용을 유지한다.
- 개인 공간 전체 Cloud 삭제의 authority/purge와 오래된 writer·importer의 부활 차단은 아직 완료되지 않았다. 로컬 삭제나 지원 상태 확인을 전체 삭제로 표시하지 않는다.
- 날짜·목록·단일 작업의 전용 읽기와 앱의 중복 정렬 제거를 구현했다. 반복 snapshot의 원본 정렬은 actor 내부 메모리에 재사용하고 모든 원본 쓰기에서 무효화한다. 첫 조회와 변경 뒤 첫 조회는 원래 전체 정렬을 수행하며 배열 buffer 하나를 추가로 보유한다. Today·위젯은 실제 기록의 순서 계약을 유지한다. 대량 데이터 cold open·paging·Spotlight의 안전한 증분 갱신과 새 source의 정량 성능·메모리 검증은 보완 대상이다. 10000개 작업·100000개 기록의 SQLite 측정, 명령·archive 왕복과 실제 기기 Q-086을 구분한다.
- 편집자는 한 명만 등록하고 중앙 선택 변경을 보호한다. 변경 없는 자기 편집은 요청 경로로 즉시 전환·닫고, 수정된 초안은 확인 뒤 자기 등록만 해제한다. 저장 실패·pending은 원문을 유지하며 오래된 저장 응답이나 다른 창의 닫기는 새 편집자를 해제하지 않는다. 실제 두 창·관측 재시작·원격 이벤트의 수용은 별도로 필요하다. 창별 독립 선택과 텍스트 포커스는 공유 모델의 남은 제약이다.
- 설정 소유권 분리는 저장 공간 전환 중 설정을 유지하고 공유 설정 내용·삭제 보호를 보존한다. 새 System 회귀가 포함된 403 소스의 SwiftPM 검사는 통과했다. 실제 Mac 두 창의 toolbar·Cmd+,·닫기·owner 창 종료 검증은 아직 필요하다. 기존 Native 6개 사례의 설정 페이지·고유한 닫기 검사와 전체 게이트는 변경하지 않았다. 일반 탐색·작업 선택·정리 표시의 창별 분리는 이번 수정에 포함하지 않는다.
- 입력 제출 보호는 독립 정적 검토와 403 소스의 SwiftPM 검사 및 iPhone 앱·단위·통합 단계를 통과했다. 추가 회귀의 개별 로그와 연속 조작 UI 검증은 남아 있다. 앞서 관측한 Batch UI 조회 실패의 원인이나 해결로 단정하지 않는다. 저장 뒤 입력 포커스 복귀와 pending 안내·재시도도 실제 플랫폼에서 확인한다.
- 플랫폼마다 밝은/어두운 화면, 큰 글자, 좁은 창, 키보드, VoiceOver, Reduce Motion/Transparency, iPad Split View와 Mac inspector를 확인한다. UI 실패를 skip하거나 assertion·typed 수용 게이트를 줄여 통과시키지 않는다.
- 새 source의 실제 IPA·공증 DMG·GitHub Release 자산을 확인한다. 인증서 사전검사, 빌드, archive, 공증, 게시 결과를 구별한다.

모든 테스트와 앱 빌드는 사용자 지정대로 GitHub Actions 러너에서 실행한다. 원본 문서·도메인 불변식·명령/reducer·멱등성·원본 우선 저장·stale/Undo 보호를 보존하며, 검사 결과가 없는 부분은 미검증으로 남긴다. 새 오류를 근거 없이 SDK 내부 원인으로 단정하지 않는다.

0145 Phone Adaptive의 검색·상세 사례는 미루기 버튼의 실제 스크롤 소유자 1개를 찾고 위로 3회 스와이프한 뒤에도 `hittable=false`로 실패했다. 마지막 버튼 프레임은 `(16, 797, 152.667, 61)`, 소유자 프레임은 `(0, 145, 402, 729)`였지만, 이 전체 프레임이 실제 조작 가능한 본문 영역이라는 근거는 없으며 당시 탭 막대·안내 영역의 기하와 전후 이동량은 기록되지 않았다. 이를 구분하도록 기존 reveal 반복이 이미 읽은 대상·소유자 프레임의 첫·직전·마지막 값과 수행한 스와이프 방향만 보관한다. 해당 Phone 사례의 `postponeStarted/taskPostpone` 요청이 기존 시간·소유자 검사에서 실패한 뒤에만 foreground·단일 창·동일 대상 소유를 확인하고, 그 창의 고정 안내 텍스트·닫기·Undo·재시도 및 native tab bar의 개수와 고유한 경우의 제한된 기하를 읽는다. 부분 요소와 대상의 양수 면적 교차는 전체 안내 영역이나 실제 가림 원인의 확정이 아니며, 불명확한 값은 null로 남긴다. 새 진단은 같은 소스·사례·요청의 기존 소유 진단과 실패 종료가 있어야 수용한다. 앱 컨테이너·레이아웃·PNG·성공 경로의 AX 조회·15초/8회 제한·기존 조작과 assertion·전체 접근성 감사·typed 수용 게이트는 변경하지 않았다. 개인정보·형식·경계·귀속·실패 후 활동 거절 회귀를 추가했으며 실제 Swift SDK 수용과 회귀 실행은 다음 Actions에서 확인한다.

정리 저장 후처리를 검토하면서, 계정 변경으로 이전 공간을 격리한 뒤 늦은 일반 명령 응답이 pending·재시도 봉투를 다시 설정하는 경로를 확인했다. 이 상태에서는 pending 보호가 기기 전용 공간으로의 명시적 복귀를 막고, 연결이 해제된 Cloud actor의 재시도도 같은 pending을 해제하지 못한다. 명령 진입 당시 저장소 actor와 관측 ID를 고정하고 계정 확인·원본 실행·진단 기록·화면 갱신의 await 뒤에 재검증하도록 보완했다. 공통 결과 처리의 직접 위젯 호출도 같은 범위를 전달하며, 기존 위젯·상세·선택기 소유권과 원본 결과·명령 키·봉투는 유지한다. 오래된 결과는 false로 반환해 호출부의 성공 후 닫기·정리 요약·설정 반영을 막으며, 같은 저장소·관측 안에서 시트만 닫는 경우의 저장과 재시도는 바꾸지 않는다. 현재 AppModel을 직접 실행하는 테스트 타깃이 없어 이 상태 경합을 기존 Store 회귀의 통과로 대신하지 않으며, 별도 상태를 복제한 테스트나 새 타깃은 추가하지 않았다. 실제 SDK 컴파일과 저장 중 계정 변경 뒤 기기 전용 복귀, 같은 공간의 정리 재개·Undo·원래 봉투 재시도 수용은 Actions 및 기기 검증으로 남아 있다.

날짜를 정한 연속 입력에서는 저장 성공 뒤 다음 입력의 날짜를 nil로 초기화할 때 성공 안내까지 다시 숨기는 경로를 수정했다. 사용자 날짜 선택·해제의 이전 안내 숨김과 포커스 조건은 유지하며, 일반 저장·분할 저장·원래 영수증 재확인의 성공 초기화에서는 안내를 보존한다. 원본 UX 명세의 날짜 지정 성공 안내와 연속 입력 계약(FR-001/030, Q-001/079)에 연결한다. 기존 Adaptive plannedCapture의 정확한 날짜 성공 안내·기본 미지정·실제 저장 assertions는 변경하지 않았다. 소스 경로와 독립 검토에서 확인한 수정이며, 해당 사례는 이전 감사 단계에서 실패했으므로 실제 증상 재현·후속 Actions 수용과 구분한다.
