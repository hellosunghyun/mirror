# 미러 전체 앱 개선 기준

사용자가 요청한 방향은 쉽게 넣고 쉽게 미루기, 심플하고 모던한 UI, iPhone·iPad·Mac에 맞는 화면 분배다. 원본 FR 30개, QA 87개, D-01~16 및 G-WIDGET·G-SYNC·G-DELETE·G-UX의 전체 범위를 유지한다. 소스 구현·Actions 통과·실제 화면 검토·실기기 수용을 각각 기록한다.

## 주요 흐름의 수용 기준

| 흐름 | 기대하는 행동 | 유지할 보호 |
|---|---|---|
| 빠른 입력 | 입력 열기와 저장을 중심으로 제목만 넣을 수 있다. 메모·링크·날짜는 필요한 때 펼친다. | 미검토 항목은 Today가 아니다. 실패·pending 때 초안과 request를 유지한다. |
| 빠른 미루기 | 목록에서 바로 내일로 미루거나 날짜 선택을 연다. 여러 일의 저장 성공 뒤 일반 목록으로 복귀한다. | 화면에 보인 작업 ID·맥락만 쓰며 실제 마감은 바꾸지 않는다. 취소·실패는 성공으로 닫지 않는다. |
| 상세 편집 | 내용·계획·마감을 구분하고 수정한 초안의 닫기를 확인한다. | 자동 저장하지 않는다. stale content·원본 저장·Undo 계약을 보존한다. |
| 적절한 화면 분배 | 휴대폰은 탭과 상세 화면, iPad·Mac은 사이드바와 필요한 때 여는 상세를 쓴다. 고급 설정은 별도 화면에서 찾는다. | 작은 창·큰 글자·키보드에서도 중요 동작과 안내에 접근한다. |
| 실수 복구 | 실제 성공 안내와 Undo, 오류·재시도 상태를 구분한다. | 오래된 문구의 자동 성공 판단과 Undo 유실을 피한다. |

## 전면 검토에서 찾은 문제

| 분야 | 개선 내용 | 검증 연결 |
|---|---|---|
| 입력·선택 | 연속 입력 옵션 접기, 선택 안내 간소화, 성공 후 목록 복귀 | FR-001/018/030, Q-001/003/075/076/079; Native·Batch 실제 입력 |
| 버튼 접근성 | iPad 상단 버튼과 Undo·재시도의 실제 label 영역에 iOS44pt 요청 | FR-025/030, Q-076/079; native frame·Adaptive 큰 글자·좁은 화면 |
| 상세·마감 | 마감 추가를 직접 찾게 하고 편집 중 닫기의 초안 보호 | FR-014/018/030, Q-025~028/030/071/075/078/079 |
| 설정·탐색 | 진단·백업·삭제의 별도 화면, 명시적인 오늘 복귀 | FR-007/020/022/023/025/030, Q-011~014/061/063~066/074/076/079/081/085 |
| 로컬 삭제 | 앱 소유 migration 백업·projection 격리 자료도 정리 | FR-024/025, Q-063/064; 중첩 자료 제거·다른 파일/root·symlink 대상 보존 |
| 시스템 안내 | Today 인텐트의 50개 표시 제한을 전체 개수와 혼동하지 않게 한다 | FR-017/030, Q-046/047/079; 0·50·51개 경계 |

## 전체 완료까지 남는 구현과 검증

- App Group·iCloud Container의 실제 Apple 등록과 서명 entitlement 연결이 필요하다. 현재 빈 설정을 임시 경로의 성공으로 대체하지 않는다. 위젯·공유 확장·실제 두 기기 동기화의 수용을 유지한다.
- 개인 공간 전체 Cloud 삭제의 authority/purge와 오래된 writer·importer의 부활 차단은 아직 완료되지 않았다. 로컬 삭제나 지원 상태 확인을 전체 삭제로 표시하지 않는다.
- 대량 데이터 cold open·paging·작은 시스템 snapshot·Spotlight의 증분 갱신은 실제 성능 baseline과 함께 보완한다. 10000개 작업·100000개 기록의 SQLite 측정, 명령·archive 왕복과 실제 기기 Q-086을 구분한다.
- 편집 초안의 닫기 보호와 여러 창·다른 작업 선택의 소유권은 별도의 수용 과제다. 공유 모델의 기존 다중창 구조를 단일 화면 수정으로 해결했다고 기록하지 않는다.
- 플랫폼마다 밝은/어두운 화면, 큰 글자, 좁은 창, 키보드, VoiceOver, Reduce Motion/Transparency, iPad Split View와 Mac inspector를 확인한다. UI 실패를 skip하거나 assertion·typed 수용 게이트를 줄여 통과시키지 않는다.
- 새 source의 실제 IPA·공증 DMG·GitHub Release 자산을 확인한다. 인증서 사전검사, 빌드, archive, 공증, 게시 결과를 구별한다.

모든 테스트와 앱 빌드는 사용자 지정대로 GitHub Actions 러너에서 실행한다. 원본 문서·도메인 불변식·명령/reducer·멱등성·원본 우선 저장·stale/Undo 보호를 보존하며, 검사 결과가 없는 부분은 미검증으로 남긴다. 새 오류를 근거 없이 SDK 내부 원인으로 단정하지 않는다.
