# 쉽게 넣고 쉽게 미루는 화면

2026-10-02 사용자의 요구에 따라 추가·미루기를 우선하고, 한 화면에 모든 설정과 정보를 펼치지 않는다. 전체 제작 범위와 [원본 UX](../postpone-app-docs/02_UX_AND_SCREEN_SPEC.md)는 유지한다.

[전체 앱 재검토](FULL_APP_REVIEW.md)에 제품 흐름·데이터 보호·성능·시스템 표면·실제 Actions 실패와 출시 조건을 함께 기록한다. 메뉴 막대 입력은 제출 token과 원문을 보존하며, 원본 저장과 projection 갱신이 확인된 자기 token의 성공만 소비한다. 다른 창의 저장이 메뉴 전용 성공 결과를 덮지 않으며, 이전 제목 재시도가 성공해도 새 제목을 지우지 않는다. 동기적인 진행 guard는 빠른 연속 저장을 막고 실패·pending은 원문을 유지한다. 실제 Mac 메뉴·재시도·focus 전달과 새 소스의 SDK/UI 수용은 아직 미검증이다.

다중 창 입력은 시작한 scene와 불변 입력 방식·저장 공간 세대에 연결한다. 다른 창이나 오래된 닫기·완료 요청이 현재 입력을 닫지 못하며, 공간 연결이 바뀐 초안은 원문을 유지하고 저장 전에 안내한다. loading 중 입력 요청은 시작 완료 뒤 만들고, Mac Cmd-N은 focused scene의 명시적 입력 action을 사용한다. scene가 소유하는 수명 token은 coordinator에서 weak로 참조해 실제 해제된 요청을 다음 입력 열기에서 회수한다. 창이 가려지거나 focus가 바뀌었다는 이유로 초안을 닫지 않는다. 상태 회귀 6개와 알림 capture 거부 assertion2개를 작성했으며 SDK compile·실제 두 창·창 종료 수명·포커스·SwiftUI dismiss 전달은 GitHub Actions와 native 수용 전까지 미검증이다.

2026-10-03 후속 제작: 기본 입력은 제목·저장만 요구하고, 접힌 메모·링크·날짜에서 오늘·내일·다른 날짜·주를 직접 선택할 수 있다. 제목과 선택한 계획은 하나의 생성 원본으로 저장하며, 달력 열기·탐색·취소는 기존 선택의 날짜/context를 갱신하거나 저장하지 않는다. 아래의 선택적 날짜 미구현 기록과 이전 실패는 과거 이력이다. 새 소스의 실제 Actions 결과는 아직 별도로 확인한다. 검색 중 미지정 목록의 전체 검색 범위와 휴지통 제외를 명시하며, 큰 글자에서는 안내/동작을 세로로 나누고 참고 일정 열을 생략한다. Mac/넓은 iPad는 작업의 별도 드래그 손잡이와 날짜·요일 미정 드롭을 제공하고 기존 버튼 대체를 유지한다. 위젯의 다른 날짜 저장 성공 뒤에는 이어서 정리·오늘 목록을 선택하며, 실제 저장 확인 전에는 완료 화면을 열지 않는다. [전체 제작·수용 계획](COMPLETION_PLAN.md)을 따른다.

부분 정리 뒤 새 입력을 넣는 경로도 기존 실제 UI 사례 안에서 검사한다. 남은 카드의 작업 ID와 원문을 보존하고, 기본 `이어서 정리`로 그 카드만 재개해 내일로 보낸다. 새 입력은 기존 큐에 자동 유입되지 않으며 같은 ID·원문·미지정·미완료로 보관함에서 다시 찾을 수 있어야 한다. 기존 여섯 사례·46장·32개 XCTFail·대기 제한은 유지하고 assertion14개를 추가한다. 앞선 iPad 표시·숨김9개와 합쳐 authored assertion은135개이며, 작성·정적 원문 보존 검토와 실제 Actions 통과를 구별한다.

소스 `1a2e00b`의 추가 UI7에서 세 플랫폼 기본 SDK 빌드는 성공했으나 Mac 실제 UI는 큰 글자 환경의 접근성 값 비교와 실제 창 크기 조절에서 실패했다. 실패 위치와 좁은 창 조절 시작까지의 도달 지점은 확인했으며 실제 환경 값·조절 전후 좌표는 아직 미관측이다. 후속 진단은 실제 SwiftUI 환경의 고정 크기 이름과 이미 읽은 창 좌표만 남기며 기존 기대값·동작·15초 대기·전체 접근성 audit·20분 native 제한을 유지한다. 관측값을 얻기 위한 변경을 제품 문제 해결이나 UI 수용으로 기록하지 않는다.

후속 소스 `ed384fb`의 추가 UI8 Mac에서는 네 사례 모두 실제 환경 이름이 `accessibility5`였고 접근성 contain 그룹의 값은 빈 문자열이었다. 좁은 창은 모서리 드래그 전후 모두 1024×674였으며 원래 15초 대기를 통과하지 못했다. Mac은 같은 실제 환경에서 만든 정확한 접근성 이름을 검사하고 iOS의 값 검사는 유지한다. 창은 둥근 모서리 대신 오른쪽·아래쪽 가장자리를 직접 조절하고 첫 조절 뒤 실제 좌표를 다시 읽는다. 최종 폭760–800·높이520–640·기존보다 좁음·15초 대기·전체 접근성 audit·20분 native 제한은 유지한다. 모서리 hit나 SDK의 실제 실패 원인은 미확정이며 수정의 통과는 다음 Actions로 확인한다.

같은 추가 UI의 입력 ID 네 개에만 TextField/TextView 조회를 사용하고, 나머지는 원래 일반 고유 요소 조회를 사용한다. 스크롤 반복 한 번 안에서는 실제 소유 surface의 경계를 재사용하며 다음 반복과 스크롤 뒤에는 새로 읽는다. 소유·hittable·전체 화면 포함·중복 거절·8회/15초 조건과 모든 기존 사례·사진은 유지한다. 중복 조회 감소를 실제 시간 절감이나 이전 실패의 원인 해결로 보고하지 않는다.

장문 상세 제목도 기본은 3줄 미리 보기다. 기존 SwiftPieces의 실제 폭·글자 크기 측정에서 잘릴 때만 더 보기·접기 Button을 제공하며, 전체 원문·접근성 내용·복사와 편집을 보존한다. 새 작업을 선택하면 제목은 다시 접히고 메모의 기존 기본값은 유지한다. 기존 내일 배치·검색 사례의 제목을 정확히500자로 강화하여 목록·상세 원문과 실제 펼침·접기·Button 역할을 검사한다. 기존135개 assertion에8개를 더해 authored143개이며, 여섯 사례·원본46장·원래 helper/대기 제한·501자 거부 회귀는 유지한다. 추가된 두 조작과 대기는 기존 Mac15분·iPhone/iPad20분 UI 단계 예산 안에서 검증하며 실제 SDK·3줄·펼친 원문·화면 배치의 수용은 Actions 대기다.

후속 화면 분배는 정리 카드의 제목도 기존 ExpandableText의 3줄 미리보기로 제한하고, 원문을 읽는 같은 표시 paragraph의 접근성 focus와 새 작업의 접힘 초기화를 보존한다. 여러 개 선택 버튼은 실제 membership의 선택됨·선택 안 됨을 전달한다. 월 달력은 7×44pt가 확보되는 폭에서만 격자를 쓰고 좁으면 기존 전체 날짜 목록으로 전환한다. 실제 계획·20개 제한·취소·월 이동·큐와 명령은 유지한다. 2개·20개 선택의 실제 화면·VoiceOver 수용은 아직 별도 검증 대상이다.

소스 `09bab98`의 추가 UI10 Mac SDK 빌드는 성공했고 실제 환경 label 비교 뒤 필수 요소의 존재·고유 조회에서 네 사례가 실패했다. 실제 실패 ID는 미관측이며 두 가장자리 조절 뒤에도 창은1024×674였다. 기존 Mac native helper와 같이 공통 조작을 마우스 클릭으로 보내고 iOS 탭을 보존한다. 같은 좌표의 Mac 드래그도 마우스 API로 바꾸며 최종 크기·15초 대기·전체 audit·모든 assertion을 유지한다. 새 좌표 API의 실제 SDK 확인과 실패 해결은 다음 Actions 대상이다. 일반 native 입력 helper에서는 Mac에서 사용하지 않는 입력 전 value 조회만 iOS 분기로 옮기며 동작·최종 exact 원문 검사는 유지한다. 실제 시간 절감은 미관측이다.

GitHub Release 게시에는 선택적 MIRROR_RELEASE_TOKEN을 연결한다. 기존 기본 토큰으로 게시 POST가403일 때 사용할 mirror 전용 Contents 읽기/쓰기 토큰이며 서명·공증·자산 검증은 유지한다. 등록 값은 채팅이나 Git에 넣지 않고 [배포 안내](ADHOC_RELEASE.md)의 gh 비공개 입력을 사용한다. 토큰 등록과 실제 게시 성공은 별도로 확인한다.

## 기본 흐름

- 추가는 제목 입력과 저장이 기본이다. 메모와 원문 링크는 접힌 부가 영역이며 자동으로 웹 내용을 가져오지 않는다.
- 날짜를 정하지 않은 새 작업은 보관함에 저장한다. 추가만으로 오늘 할 일이나 완료 상태를 만들지 않는다.
- 오늘 화면의 정리 버튼은 사용자의 명시적 재개로 처리한다. 남은 카드가 있으면 `이어서 정리`로 같은 세션을 열고 새 입력을 끼워 넣지 않는다. 정리를 마친 뒤 새로 넣은 일은 이 기본 버튼으로 다시 정리할 수 있으며, 자동 위젯의 닫힌 주기 정책은 유지한다.
- 이어 정리의 고정 큐에서는 이미 확인한 계획과 완료·삭제·미래·미지원 작업만 제외한다. 여전히 유효한 현재 카드의 버전과 token은 유지하고, 새로 노출되는 다음 카드나 사용자가 명시적으로 최신화한 카드만 갱신한다. 최신 상태 조회가 실패하면 기존 카드와 오류를 보존한다.
- 목록의 `미루기`는 오늘·내일을 먼저 제공하고, 다른 날짜 달력은 펼쳐서 사용한다. 취소는 저장하지 않는다.
- 목록의 긴 제목은 3줄 미리 보기로 표시한다. 저장한 원문과 전체 접근성 이름은 유지하며, 상세는 3줄 미리 보기와 필요한 경우의 더 보기로 전체 제목을 확인할 수 있다.
- 날짜 선택에서는 긴 제목을 두 줄 미리 보기로 표시하고 접근성 이름에는 전체 제목을 유지한다. 여러 작업은 개수만 먼저 보여 주고 제목 목록은 펼쳐 확인한다. 일반 글자 크기에서도 버튼이 가용 폭에 맞지 않으면 세로로 나누어 핵심 날짜 선택을 압축하지 않는다.
- 여러 개 선택은 현재 검색·필터에 보이는 미완료 작업만 대상으로 한다. 숨은 작업은 선택에서 빠지고, 선택을 마친 뒤 다시 시작하면 빈 선택으로 시작한다.
- 열린 작업은 상세의 `내일로 미루기`, 행의 보조 제스처·접근성 동작 또는 메뉴로 내일에 바로 배치한다. 보관은 별개의 명시적 동작으로 유지한다.
- 바로 미루기도 표시한 작업의 버전과 계획 기준을 고정한다. 저장 전 성공을 표시하지 않고, 실제 마감 이후 배치는 확인하며 기존 Undo를 제공한다.
- 이미 내일에 배치한 작업에는 즉시 내일 행동을 표시하지 않는다. 이 행동으로 같은 날짜를 다시 저장해 이전 이동의 Undo를 바꾸지 않으며, 일반 날짜 선택은 계속 제공한다.
- 선택한 상세 작업의 직전 변경은 상세에서 되돌린다. 다른 작업이나 여러 작업의 변경은 목록의 저장 안내에서 되돌릴 수 있어 상세가 열려 있어도 진입을 잃지 않는다.
- 오래된 이력을 되돌리려다 거절되어도 최근 변경의 되돌리기 후보를 유지한다. 상세 자체에 실패 이유를 표시하며, 최근 미루기를 바로 되돌릴 수 있다. 저장 결과를 확인하는 동안 상세의 새 날짜 선택은 비활성화한다.
- 변경 이력은 기본으로 접혀 있다. 넓은 펼침 버튼에 접힘 상태를 표시하고, 펼침 제어와 내부 되돌리기 버튼의 접근성 식별을 구분한다.

## 화면에 남기는 정보

| 화면 | 기본으로 표시 | 필요할 때 표시 |
|---|---|---|
| 오늘 | 오늘에 정한 일, 실제 마감, 정리 진입 | 정리 옵션·결과, 완료한 일 |
| 보관함 | 검색, 선택한 필터, 작업과 미루기 | 여러 개 선택과 일괄 배치 |
| 일정 | 선택 날짜의 작업·실제 마감·읽기 전용 약속 | 주간 탐색, 요일 미정 작업, 선택 권한 |
| 작업 상세 | 제목, 계획, 완료, 내일로 미루기·다른 날짜 | 메모·링크, 변경 이력·보관·휴지통, 아직 없는 마감 추가 |
| 정리 | 카드 한 개와 오늘·내일, 세 보조 목적지 | 주간 날짜 패널, 다른 날짜, 작업 상세 |

이미 지정한 실제 마감과 충돌 안내는 접어 숨기지 않는다. 완료된 작업에는 실행할 수 없는 계획 변경 버튼·메뉴를 표시하지 않는다.

설정에서 캘린더 접근을 거절하거나 일정을 불러오지 못하면 캘린더 설정 영역에 이유를 표시한다. 선택 권한 없이도 할 일 입력과 날짜 배치를 계속 사용할 수 있다.

Mac 메뉴바의 빠른 입력도 원본 저장과 화면 갱신 대기 동안 제목 편집을 잠근다. 제출한 문자열을 저장하는 비동기 구간에서 새로 입력한 내용이 성공 처리에 의해 지워지는 경로를 막기 위한 조건이며, 일반 입력과 메뉴 저장 버튼의 기존 조건을 사용한다. 실패 시 원문 보존과 입력 복귀, 실제 메뉴의 저장·갱신 대기 동작은 별도 native 검증 대상이다. 기존 메인 시트 UI 검사를 메뉴바 입력의 검증 결과로 대체하지 않는다.

상세 내용을 편집하는 동안 배경 목록의 즉시 내일 배치는 숨기고, 보이는 미루기 버튼은 비활성화한다. 행과 버튼의 폭을 유지하며 편집을 저장하거나 취소하면 다시 사용할 수 있다. 이 조건은 완료·삭제·작업 선택의 기존 경로를 바꾸지 않는다.

설정 첫 화면에는 정리·시간대·알림·캘린더·동기화·개인정보를 유지하고, 진단 기록과 내보내기·복원, 데이터 삭제는 각각 눌러 여는 화면으로 나눈다. 페이지를 이동해도 같은 설정 부모가 동의·복원 미리 보기와 파일 선택·내보내기·확인을 소유한다. 실제 기기 데이터 삭제의 두 확인은 유지하며, 아직 지원하지 않는 iCloud 전체 삭제는 한 번의 일반 상태 확인으로 안내한다. 일정의 `오늘로`는 현재 계획 시간대의 오늘로 살펴보는 날짜만 옮기고 작업의 계획을 바꾸지 않는다. 새 페이지의 파일 처리·복귀·접근성과 오늘 이동은 실제 Actions 검증 전까지 미검증이다.

## 플랫폼별 배치

입력은 스크롤 가능한 작은 작성 영역과 키보드 위 저장·오류 영역을 사용한다. iPhone·iPad의 세 메인 화면·참고 일정·입력 및 미루기 제목은 작은 내비게이션 제목을 사용한다. 검색 키보드가 열릴 때 큰 제목이 접히는 전환을 줄이지만, 이전 검색 툴바 실패의 원인 해결은 실제 결과까지 단정하지 않는다. 입력 시트는 시스템의 콘텐츠 맞춤 크기를 요청하며 코드의 크기 요청과 실제 표시 크기의 수용을 구분한다. Mac은 입력 필드를 왼쪽 정렬하고 작은 창의 최소 크기와 이상적인 크기를 제공한다. ⌘Return은 저장, 일반 Return은 여러 줄 입력이며 하드웨어 키보드 지원의 실제 검증은 별도다.

iPhone과 좁은 iPad 창은 세 탭, 넓은 iPad·Mac은 사이드바를 사용한다. 넓은 iPad의 보조 일정은 기본으로 숨기며, 기존 가용 폭 조건에서만 보이는 상단 `보조 일정 표시·숨기기` 버튼으로 요청할 때 표시할 수 있다. 표시·숨김 선택은 해당 창을 쓰는 동안 유지하고, 새 창의 기본은 숨김이다. 작업 선택 때 보조 일정 대신 상세를 제공하며 큰 글자에서는 보조 일정과 표시 버튼을 생략한다. 상세는 기본적으로 닫혀 있고, 목록과 선택한 상세의 기존 폭 계약을 유지한다. 부가 입력을 접을 때 숨긴 입력란의 포커스는 제목으로 옮긴다. 기존 iPad 가로 캡처는 기본 숨김을 확인한 뒤 표시 버튼을 직접 눌러 보조 일정을 켠 상태를 기록하고, 캡처 후 다시 숨김을 확인한다.

드래그 손잡이는 Mac·regular iPad의 일정 화면, 또는 보조 일정이 실제 표시되는 오늘·보관함 목록에만 제공한다. 일반 목록·정리·상세에는 기본으로 손잡이를 두지 않으며, 보조 일정을 숨기면 목록의 손잡이도 사라진다. 좁은 iPad·iPhone·큰 글자에서는 기존 미루기 버튼과 날짜 선택을 사용한다. 날짜·요일 미정 드롭과 외부 약속의 읽기 전용 정책, 목록의 오늘·내일 선택은 유지한다. 새 표시 범위와 토글의 실제 조작·키보드·접근성·화면 배치는 Actions 검증 전까지 미검증이다. 기존 여섯 UI 사례와 46장 캡처는 변경하지 않는다.

compact iPhone은 화면 제목과 추가·설정을 전체 탭 바깥 공통 상단 행에 배치한다. 제목은 기존 오늘·일정·보관함과 같은 값이고, 두 버튼은 기존 동작·한국어 라벨·식별자·추가 단축키를 유지한다. 버튼에는 최소 44pt 터치 영역을 요청하며 헤더 전체 높이를 고정하지 않는다. 이 경로의 시스템 내비게이션 바는 숨기고 각 탭의 내비게이션 스택·본문·저장·오류·Undo 안내를 세로로 나눈다. 안내는 필요한 세로 높이를 먼저 확보하고 본문은 남은 공간을 사용한다. 시스템 상태 표시줄 높이나 기기별 좌표로 여백을 보정하지 않는다. iPhone의 regular 경로와 iPad·Mac은 기존 툴바와 안내 위치를 유지하며, 오류 본문·재시도·Undo를 축소하거나 숨기지 않는다.

소스 `0018ab2`의 기본75 iPhone에서는 일정 탭 전환 뒤 추가 버튼의 실제 y좌표가 8pt이고 상태 표시줄의 아래 경계가 54pt여서 기존 겹침 검사가 실패했다. 초기 오늘과 검증 오류 복귀에서는 같은 버튼이 70pt에 있었다. 상단 행과 저장 안내를 각 탭의 내비게이션 스택 밖에 두고 본문만 스택에 넣어, 탭이 소유한 시스템 안전 영역에서 두 행을 배치한다. 정확한 SDK 내부 원인은 미확정이며 숫자 여백·추가 대기·검사 약화 없이 기존 회귀로 새 소스를 검증한다. 같은 소스의 다크32는 세 플랫폼 검사와 원본46장 게시가 성공했다.

후속 소스 `88bb2bf`의 다크33 iPhone은 일반 탭 경계와 입력 오류 복귀를 포함한 입력 사례를 통과했지만 검색 키보드가 열린 상태의 추가 버튼 검사가 실패했다. 해당 버튼은 실제 창 안에 있으나 상태 표시줄 아래에 있지 않고 누를 수 없다는 고정 진단을 확인했다. 정확한 좌표와 SDK 내부 원인은 미확정이다. 상단 행 하나를 compact iPhone의 TabView 바깥 `safeAreaInset(edge: .top)`에서 소유하고 제목은 현재 선택한 목적지로 표시한다. 각 탭의 스택·본문·저장 안내는 유지하며 기기별 여백이나 키보드 무시, 검사 약화를 추가하지 않는다. 새 소스에서 동일한 탭·검색 키보드·Undo 경계와 원본을 다시 검증한다.

주간 미루기의 일곱 날짜는 한 그룹 안에 배치한다. 가용 폭이 328pt 이상인 기본 글자 화면은 두 열, 더 좁거나 접근성 글자 크기에서는 한 열로 표시한다. 전체 날짜 이름은 줄바꿈하며 각 버튼은 최소 44pt 높이와 전체 셀의 터치 영역을 갖는다. ‘요일은 나중에 정하기’는 별도 행으로 유지하고, 지난 날짜 비활성화·취소·계획만 저장하는 기존 규칙을 바꾸지 않는다. Mac은 주간 선택에만 이상적인 시트 높이 560pt를 요청하며 다른 미루기 시트는 400pt를 유지한다. 실제 크기는 시스템의 가용 공간에 따르고 Form 스크롤은 유지한다.

## 검증과 남은 조건

2026-10-03의 화면 밀도 수정은 iPad 기본 보조 일정 숨김을 유지하며, 기존 가로 배치 검증 전에 표시 버튼을 직접 누르고 캡처 뒤 다시 숨기는 회귀를 추가한다. 기존 112개 assertion·32개 XCTFail·여섯 사례·46장 계약과 가로 배치 helper를 보존하고, 고유 버튼·한국어 이름·실제 표시 상태 검사 9개를 더해 assertion은 121개다. 별도 큰 글자 사례에는 정리를 끝낸 뒤 새 일을 넣고 기본 버튼으로 재개하는 회귀를 추가한다. 새 소스의 실제 원격 결과는 아직 미검증이다.

자동 테스트와 앱 빌드는 GitHub Actions에서만 실행한다. 기존 여섯 UI 사례와 기존 검사·실패 조건·시간 제한·원본46장 계약을 유지하고, 상세에서 내일 배치 → Undo → 오늘 목록 복귀를 추가한다. 제목과 미완료 상태의 보존, 배치 후 반복 내일 버튼의 부재 및 날짜 선택 창을 불필요하게 열지 않는 것도 검사한다.

기존 완료·Undo 사례에서 이전 오늘 배치의 실제 이력 ID를 읽고, 내일 배치 뒤 해당 과거 Undo가 거절되는 것을 확인한다. 오류가 상세에 보이고 내일 계획을 유지한 뒤, 직전 변경 Undo로 오늘을 복원하고 오류가 사라지는지를 같은 실제 저장 경로에서 검사한다. 기존 화면 캡처 위치와 수는 유지하며 실제 Actions 결과는 별도로 확인한다.

이전 입력의 검증 오류는 해당 오류의 대입 revision으로 소유를 구분하여 닫기·재진입에서만 정리한다. 이후 다른 저장·계정 오류가 대입됐으면 보존한다. 긴 제목 오류에서 입력 원문·키보드 위 오류·저장 버튼을 검증하던 조건은 유지하고 닫힌 입력의 오류 잔류도 검사한다. 기존85개에서99개로 늘었던 assertion은 유지한다. 다중 선택의 실제 검색·재진입 회귀4개와 이력 펼침의 실제 Button 역할1개를 추가해 합계104개이며 실제 실행 결과와 구별한다.

소스 `c2bd3f`의 기본72는 세 플랫폼의 UI18개와 단위·도메인 검사를 통과했지만 다크29는 iPhone·iPad에서 실패했다. iPhone은 긴 제목 오류를 닫고 보관함으로 돌아온 뒤 추가 버튼이 존재·활성 상태임에도 누를 수 없고 시스템 상태 표시줄 아래에 있다는 검사도 통과하지 못했다. iPad는 stdout의 5개 사례 통과만 관측했고 마지막 사례와 최종 실행·summary·guard·xcresult 결과는 미관측이다. 실제 SDK·인프라 원인은 미확정이며 과거 통과로 이번 실패를 대체하지 않는다.

본문 상단 행 변경에는 같은 긴 제목 오류 복귀 지점에서 기존 `verifyPhoneNavigation`을 호출하는 회귀를 포함한다. 새 조작·대기·사진을 추가하지 않고 기존6사례/46장과 source assertion112개·XCTFail32개를 유지한다. 실제 고유 Button·창·상태 표시줄·hittable 검사는 그대로다. CI에는 UI 명령의 반환과 결과 추출의 attempted/succeeded/failed, 별도 실패 진단 경로를 구분하는 고정 notice만 추가한다. 이 notice는 child 실행·전체 통과·실패 원인을 증명하지 않으며 timeout·기존 명령·종료 코드·검증·게시 게이트를 바꾸지 않는다. 새 소스의 실제 빌드·원본 화면·서명 릴리스는 다시 검증한다.
