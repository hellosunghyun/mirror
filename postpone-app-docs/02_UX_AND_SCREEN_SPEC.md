# 02. UX와 화면 명세

버전 0.1 / 관련: [제품 요구](01_PRODUCT_REQUIREMENTS.md), [상태 규칙](03_DOMAIN_AND_REVIEW_RULES.md), [위젯](06_APP_INTENTS_AND_WIDGETS.md)

## 1. 경험 원칙

입력할 때에는 기억만 맡긴다. 정리할 때에는 지금 하지 않을 일을 보낸다. 실행할 때에는 오늘 남긴 일만 본다. 미래로 보낸 항목의 존재를 모든 화면에서 숨기지는 않되, 반복적으로 재결정을 요구하지 않는다.

공간이 넓다고 필수 결정 항목을 늘리지 않는다. 모든 플랫폼에서 동일한 5개 목적지를 같은 순서로 제공한다. 시각 스타일은 네이티브 시스템 컨트롤과 읽기 쉬운 대비가 기본이며, 유리 효과나 애니메이션은 정보와 터치 영역을 침해하지 않는다.

## 2. 정보구조

```text
오늘
  ├ 오늘 하기로 정한 일
  ├ 실제 마감 안내
  ├ 오늘 정리 / 다시 정리
  └ 완료한 일 접기

일정
  ├ 일간 / 주간
  ├ 선택 날짜의 할 일
  ├ 이번 주 날짜 미정
  └ 기존 캘린더 약속 (선택 권한)

보관함
  ├ 새로 넣은 일 / 정하지 않은 일
  ├ 지난 계획에서 남은 일
  ├ 미래 계획
  ├ 당분간 보관
  ├ 전체 검색
  └ 휴지통 / 완료 기록

공통
  ├ 빠른 입력
  ├ 작업 상세
  └ 설정
```

iPhone은 오늘 / 일정 / 보관함 3개 탭을 기본안으로 삼는다. iPad와 Mac은 동일한 목적지를 사이드바에 둔다. 정리 화면은 네 번째 고정 탭이 아니라 오늘 화면과 위젯에서 시작하는 임시 흐름이다.

## 3. 주요 사용자 여정

### J-01. 처음 입력하기

앱 첫 실행 → “일단 넣고, 나중에 정하세요” 설명 → 바로 입력. 알림, 캘린더, iCloud, 위젯 설치를 한꺼번에 요구하지 않는다. 샘플 작업은 예시임을 표시하며 실사용 데이터에 몰래 섞지 않는다.

작업 저장 후 토스트는 “보관함에 넣었어요.”다. “오늘 할 일에 추가했어요”가 아니다. 사용자가 입력 단계에서 직접 날짜를 정한 경우에만 해당 날짜를 안내한다.

### J-02. 일간 정리

정리 진입 → “오늘 할 일인가요?” → 카드의 5개 버튼 → 확정 저장 → 짧은 날짜 피드백 → 다음 카드. 오늘 버튼도 다음 카드로 진행하지만 완료 표시는 하지 않는다.

### J-03. 주간 정리

주간 검토일에 정리 진입 → “이번 주에 할 일인가요?”와 날짜 범위 → 같은 5개 버튼. 오늘 / 내일 / 특정 날짜를 직접 고를 수 있다. 주만 고르면 세부 요일은 나중에 결정한다. 이미 미래 날짜가 확정된 일은 기본 큐에 넣지 않는다.

### J-04. 중간에 종료

“오늘은 여기까지” → “오늘에 남긴 일 3개 / 다른 날로 보낸 일 6개 / 아직 정하지 않은 일 4개” → 오늘 목록. 미검토 4개는 오늘 목록으로 이동하지 않는다. 다음 명시적 재개나 다음 정리에서 확인한다.

### J-05. 며칠 뒤 복귀

앱 실행 → 현재 날짜 기준 오늘 목록과 실제 마감 안내 → “지난 계획에서 남은 일”을 별도 정리 대상으로 제시. 기존 미완료 전부를 오늘로 바꾸지 않는다. 전체 정리를 완료하지 않아도 새 일을 넣고 오늘 작업을 완료할 수 있다.

## 4. 화면별 규격

### S-01. 첫 실행

| 항목 | 명세 |
|---|---|
| 목적 | 가치 설명 후 첫 입력까지 빠르게 도달 |
| 필수 내용 | “잘 미루면, 지금 할 일이 남는다.” / 입력과 나중 결정의 차이 |
| 기본 행동 | 첫 할 일 입력 |
| 보조 행동 | 바로 둘러보기 |
| 권한 | 이 단계에서 필수 권한 요청 없음 |
| 초기값 | 계획 시간대는 기기 시간대, 한국 환경에서는 서울. 화면에 변경 경로 제공 |

App Intent로 앱보다 먼저 입력이 들어와도 로컬 저장소를 초기화할 수 있어야 한다. 온보딩 완료 여부가 쓰기 명령의 필수 조건이 되면 안 된다.

### S-02. 빠른 입력

제목 한 줄과 저장 버튼을 기본으로 한다. 메모 / 링크 / 날짜는 접힌 부가 영역이다. 저장 이후 키보드를 유지할지 닫을지는 입력 진입점에 따라 다르다. 앱의 연속 입력은 유지, 위젯 딥링크의 단일 입력은 완료 후 오늘 화면으로 이동한다.

여러 줄을 붙여 넣으면 자동으로 N개의 할 일을 생성하지 않는다. “한 개로 저장 / 줄마다 나누기”를 미리 보기에서 선택한다. 제목이 없는 링크는 URL 자체를 제목으로 삼을 수 있으나 원문 URL 필드는 그대로 보존한다.

음성 입력은 시스템 받아쓰기 또는 단축어에서 받은 텍스트가 R1 경로다. 별도 상시 녹음 기능과 마이크 권한은 만들지 않는다.

### S-03. 오늘

```text
오늘                         [+]

실제 마감 1개
질문지 공유: 금요일까지

오늘 남긴 일
[ ] 신청 메일 보내기
[ ] 인터뷰 질문 정리

[오늘 정리]
```

실제 마감 안내는 오늘 목록과 시각적으로 분리한다. 마감이 오늘이라고 작업의 계획 날짜를 오늘로 바꾸지 않는다. 상세를 열면 “오늘에 남기기 / 날짜 바꾸기”를 선택할 수 있다.

오늘 항목이 없고 미검토 항목이 있다면 “오늘에 남긴 일이 없어요. 정하지 않은 일은 보관함에 있어요.”를 표시한다. 정리하지 않았다는 이유로 빈 오늘 목록을 “오늘 할 일 모두 완료”로 표현하지 않는다.

정리를 마친 뒤 다시 열면 오늘 목록이 기본이다. 새 작업이 들어왔다고 자동으로 정리 모드로 돌아가지 않는다. 새 항목 수를 작게 표시하고 사용자가 다시 정리를 선택하게 한다.

### S-04. 정리 카드

필수 표시: 정리 질문, 작업 제목, 지정된 실제 마감, 현재 배치가 있다면 그 날짜, 5개 목적지. 보조 표시: 원문 링크 존재, 짧은 메모 첫 줄, 앞선 결정 되돌리기. 예상 시간, 태그, 중요도 선택을 기본에 넣지 않는다.

버튼 순서와 뜻:

| 버튼 | 즉시 데이터 변경 | 후속 UI |
|---|---|---|
| 오늘 | 있음: 현재 계획 날짜 | 다음 카드 |
| 내일 | 있음: 다음 계획 날짜 | 다음 카드 |
| 이번 주 › | 없음 | 이번 주 날짜 패널 |
| 다음 주 › | 없음 | 다음 주 날짜 패널 |
| 기타 › | 없음 | 전체 달력 선택 |

앱에서는 2개 큰 버튼과 3개 보조 버튼을 기본안으로 둔다. 이는 중요도 순위가 아니라 1단계 동작과 2단계 선택을 구별하는 배치다. `오늘`에 체크 아이콘을 붙여 완료로 오해하게 하지 않는다.

정리 진행 숫자는 처리량을 독려하는 점수가 아니다. “이번에 정한 6개” 정도를 표시하며 전체 미완료 1,000개를 진행 분모로 노출하지 않는다.

### S-05. 주간 날짜 패널

작업 제목은 유지한다. 헤더에는 “다음 주 10/5–10/11”처럼 절대 범위를 표시한다. 월~일 날짜 버튼은 동일한 터치 크기를 유지한다. 이번 주 패널에서는 과거 날짜를 비활성화하고 날짜를 고를 수 없는 이유를 접근성 레이블에 포함한다.

“요일은 나중에 정하기”는 계획 주만 저장하는 명시적 행동이다. 오늘이 포함된 주를 선택한 경우 같은 날의 정리에서 바로 다시 요일을 묻지 않는다. 다음 일간 정리에서 돌아온다.

일정 정보는 권한이 있고 넓은 공간이 있을 때 “약속 2 / 할 일 3”처럼 보조 표시한다. 표시된 수만으로 “바쁨 / 가능”을 확정하지 않는다. 사용하지 않는 날짜의 빈칸을 작업 가능 시간으로 단정하지 않는다.

뒤로 가기, 바깥 탭, Esc로 닫기에서는 아무 계획도 바뀌지 않는다.

### S-06. 기타 날짜 선택

현재 작업 ID와 카드 식별자를 전달받아 바로 달력을 연다. 기본 선택값은 기존 계획 날짜 또는 오늘이며, 선택만으로 바로 저장하는 UI에서는 실수 방지를 위해 아직 변경되지 않은 초기 선택과 실제 탭을 구별한다.

한 번의 날짜 탭을 확정으로 삼되, 실제 마감 이후라는 확인이 필요하면 확인 시트로 전환한다. 위젯에서 앱으로 왔다면 앱이 홈 화면으로 강제 복귀할 수 있다고 가정하지 않는다. “이어서 정리”와 “오늘 목록”을 제공한다.

“당분간 보관”은 달력 아래 보조 메뉴 또는 작업 상세에서 선택한다. 5개 핵심 버튼을 6개로 늘리지 않는다. 과거 날짜 지정은 R1에서 허용하지 않는다. 기록 보기와 완료 날짜 수정은 이 화면의 책임이 아니다.

### S-07. 결정 피드백과 되돌리기

앱에서는 “10월 6일 화요일로 보냈어요. 되돌리기”를 짧게 표시하고 다음 카드로 진행한다. 위젯에서는 다음 카드 하단에 직전 작업의 축약 제목과 목적지를 남긴다. 토스트 자동 소멸만이 되돌리기의 유일한 경로가 되지 않도록 상세 변경 기록에서도 직전 결정을 확인할 수 있게 한다.

되돌리면 해당 카드를 다시 보여주고 새로운 결정 토큰을 발급한다. 이미 다른 기기에서 다시 배치했으면 “그 뒤에 날짜가 바뀌었어요”와 최신 날짜를 표시하며 과거 상태를 덮어쓰지 않는다.

### S-08. 정리 종료

“오늘은 여기까지”는 언제나 보인다. 카드가 0개이면 자동 종료 안내가 가능하나 오늘 목록으로 바로 이동할 수 있다. 3분이 지났다고 마지막 결정을 취소하거나 화면을 강제로 닫지 않는다.

종료 요약은 오늘에 남긴 일 / 다른 때로 보낸 일 / 아직 정하지 않은 일이다. 주만 정한 항목은 다른 때로 보낸 수에 포함할 수 있으나 날짜가 정해졌다고 표현하지 않는다. 모든 숫자는 현재 세션 처리에 대한 것인지 전체 상태인지 레이블로 구별한다.

### S-09. 일정

기본 일간 / 주간 보기에서 날짜별 할 일과 약속을 구분한다. 할 일은 날짜의 상단 목록 또는 별도 행에 놓는다. 시간 없는 할 일을 09:00 블록으로 만들지 않는다. 실제 마감은 배지 또는 독립 표시다.

요일 미정 작업은 해당 주의 별도 바구니에 둔다. 드래그로 날짜에 놓는 것은 Mac / iPad의 보조 경로다. 같은 작업에 항상 버튼 방식의 날짜 선택을 제공한다.

외부 약속은 R1에서 읽기만 한다. 약속을 드래그하여 수정할 수 있는 것처럼 보이지 않게 한다. 이벤트 권한이나 원본을 찾지 못하면 “일정을 불러오지 못했어요”와 할 일 목록을 계속 보여준다.

### S-10. 보관함

초기 보관함은 새로 넣은 일과 아직 정하지 않은 일을 중심으로 표시한다. 전체 검색은 미래 계획, 완료, 보관도 필터로 포함할 수 있다. 미래 계획을 검색 결과에 표시하는 것은 정리 큐 재등장이 아니다.

상세 상태는 “10월 6일에 하기”, “10/5–10/11 중 날짜 미정”, “아직 정하지 않음”, “당분간 보관”처럼 구체적으로 표시한다. 애매한 “나중에” 한 단어로 모두 합치지 않는다.

### S-11. 작업 상세

제목, 메모, 원문 URL, 계획, 실제 마감, 최근 변경, 완료 / 다시 열기, 보관, 휴지통을 제공한다. 계획 변경과 마감 변경을 다른 섹션과 명령으로 둔다. 반복적으로 미룬 횟수를 경고처럼 강조하지 않는다.

R1에서는 작업 분해 AI, 집중 타이머, 에너지 설문을 기본 상세에 넣지 않는다. 이후 붙이더라도 완료 조건과 계획 날짜의 의미를 변경하지 않는다.

### S-12. 설정과 상태 진단

정리 알림 시간, 주간 정리 요일, 계획 시간대, 캘린더 선택, 동기화, 개인정보 노출, 내보내기 / 복원을 둔다. 날짜 경계를 바꾸는 사용자 정의 새벽 시작 시간은 R1에 넣지 않는다.

동기화 상태는 “이 기기에 저장됨 / iCloud 동기화 대기 / 동기화 문제”로 구별한다. 실제로 다른 모든 기기가 최신이라는 사실을 확인하지 못했으면 “모든 기기 동기화 완료”라고 표시하지 않는다.

## 5. 화면 상태 공통 규격

| 상태 | 표현 | 허용 행동 |
|---|---|---|
| 초기 로딩 | 구조를 유지하는 짧은 자리표시자 | 취소 / 닫기 |
| 저장 중 | 대상 카드 고정, 중복 결정 보호 | 다음 항목으로 임의 진행 금지 |
| 로컬 저장 성공 | 목적지 확인 | 다음 카드 / 되돌리기 |
| 저장은 됐고 표시 재구축 중 | “저장했어요. 화면을 갱신하고 있어요.” | 새로고침, 동일 토큰 재시도 |
| 저장 실패 | “저장하지 못했어요. 다시 시도해 주세요.” | 원문 유지 / 재시도 |
| 오래된 화면 | “내용이 바뀌었어요. 최신 상태를 확인해 주세요.” | 갱신 |
| 날짜 경계 변경 | “날짜가 바뀌었어요. 오늘 기준으로 다시 보여드릴게요.” | 갱신 후 결정 |
| 데이터 없음 | 맥락별 정확한 빈 상태 | 입력 / 정리 / 검색 |
| 권한 거부 | 해당 기능만 제한 | 권한 없이 계속 |

## 6. 접근성 규칙

버튼 목표 크기 44pt는 제품 터치 목표로 채택한다. 공간이 부족하면 글자를 줄여 모든 버튼을 우겨 넣지 않고 더 큰 위젯이나 앱 화면으로 연결한다. 실제 WidgetFamily별 레이아웃 검증이 필요하다.

VoiceOver는 “다음 주, 10월 5일부터 11일까지, 날짜 선택”처럼 동작을 설명한다. 카드가 바뀌면 제목에 초점을 옮기고 직전 저장 결과를 짧게 알린다. 장시간 음성 안내로 다음 입력을 막지 않는다.

Dynamic Type, 굵은 텍스트, 대비 증가, Reduce Motion, Voice Control, 키보드 탐색을 테스트한다. 색만으로 계획 / 실제 마감 / 완료를 구분하지 않는다. 날짜 버튼은 요일과 숫자를 함께 읽는다. 실수 복구를 특정 제스처 하나에만 의존하지 않는다.

## 7. Mac과 iPad 동작

Mac은 사이드바, 오늘 목록, 작업 상세의 다중 열 구성을 제공한다. 앱이 활성화된 상태에서 Cmd+N은 입력, Cmd+F는 검색, Cmd+Z는 현재 UI 컨텍스트의 안전한 되돌리기를 수행한다. 정리 카드의 숫자 키 단축은 텍스트 편집 중 비활성화하며 화면에 단축키를 표시한다.

전역 단축키는 별도 구현과 충돌 처리가 필요하므로 메뉴 막대 입력보다 우선하지 않는다. 사용자 작업을 감시하기 위한 손쉬운 사용 권한을 요구하지 않는다.

iPad는 좁은 창에서 iPhone과 같은 탐색을 제공하고, 넓은 창에서는 일정을 옆에 둔다. 키보드가 가려서 날짜 선택이나 저장이 불가능해지지 않아야 한다.

## 8. 디자인 산출물 수용 범위

이 문서의 텍스트 구조는 동작 명세이지 승인된 시각 시안이 아니다. 실제 컴포넌트 치수, 아이콘, 전환 애니메이션, Liquid Glass 적용은 기기별 목업과 접근성 검증 후 정한다. UI 시안이 도메인 규칙을 바꾸면 PRD와 ADR을 먼저 수정한다.
