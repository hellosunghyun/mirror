# 01. 제품 요구사항 명세

버전 0.1 / 제안 명세 / 2026-09-30  
관련 문서: [UX](02_UX_AND_SCREEN_SPEC.md), [도메인](03_DOMAIN_AND_REVIEW_RULES.md), [QA](08_QA_AND_ACCEPTANCE.md)

## 1. 제품 개요

이 앱은 할 일을 많이 정리하게 만드는 앱이 아니라, **지금 하지 않을 일을 안심하고 미루고, 오늘 할 일을 남기는 앱**이다.

사용자는 생각난 일을 즉시 넣는다. 정리하는 시간에는 오늘, 내일, 이번 주, 다음 주, 기타로 보낸다. 정한 시점 전에는 같은 일을 다시 결정하게 하지 않는다. 정리가 끝나면 실행을 위한 오늘 목록으로 전환한다.

주된 경쟁 대상은 특정 앱이 아니라 반복적으로 전체 목록을 확인하고 날짜를 다시 바꾸는 관리 비용이다. 실제 효과는 검증 전 가설이며, ADHD 치료나 증상 개선을 주장하지 않는다.

## 2. 사용자 요청에서 확인된 방향

| ID | 확정 방향 | 구현에 미치는 영향 |
|---|---|---|
| C-01 | 미루기를 제품의 중심으로 둔다 | 일반적인 프로젝트 관리 기능보다 재배치와 재등장 신뢰를 우선 |
| C-02 | 일을 앱에 일단 쏟아 넣을 수 있어야 한다 | 입력 시 제목 외 메타데이터 강제 금지 |
| C-03 | 하루에 한 번 이번 주 일을 주 안에 배치한다 | 일간 정리와 날짜 선택 흐름 필요 |
| C-04 | 일주일에 한 번 이번 주와 다음 주 이후를 나눈다 | 주간 검토 범위와 주 단위 계획 상태 필요 |
| C-05 | 하루 3분 정도만 관리에 쓴다 | 중간 종료, 큐 재개, 불필요한 재질문 방지 |
| C-06 | 미룬 뒤 남은 일이 지금 해야 하거나 할 수 있는 일이다 | 미검토와 오늘에 남긴 항목을 명확히 분리 |
| C-07 | 특정 날짜에 배치하는 행동이 쉬워야 한다 | 바로 날짜를 선택하고 저장하는 경로 |
| C-08 | 위젯에 오늘 / 내일 / 이번 주 / 다음 주 / 기타 버튼을 둔다 | 중형 / 대형 위젯 핵심 요구 |
| C-09 | 이번 주 / 다음 주에서도 날짜를 고를 수 있다 | 해당 주의 날짜 패널과 주만 선택하는 보조 행동 |
| C-10 | Apple 생태계와 App Intents를 적극 활용한다 | 앱과 시스템 진입점의 같은 명령 처리 |

주만 정하기, 기본 검토 시각, 최소 OS, 데이터 저장 방식, 계정 정책은 대화의 방향을 구체화한 권고안이다. 상품명, 가격, 유료 기능, 공개 출시 일정은 미정이다.

## 3. 해결하려는 사용자 상황

| 상황 | 관찰할 문제 | 필요한 제품 행동 | 피할 행동 |
|---|---|---|---|
| 생각은 나지만 기록이 번거롭다 | 분류 단계에서 입력 포기 | 제목만 저장, 공유 텍스트 수용 | 필수 프로젝트 / 태그 |
| 목록은 있지만 너무 많다 | 볼 때마다 전체를 재평가 | 지금 검토해야 할 부분만 추출 | 전체 미완료 수의 상시 강조 |
| 계획을 세워도 시작하지 못한다 | 관리가 실행을 대체 | 정리 종료 후 오늘 목록으로 전환 | 끝없는 재정리 권유 |
| 며칠 앱을 쓰지 않았다 | 복귀 시 밀린 목록 압박 | 마감과 미검토 분리, 중간 종료 | 연속 기록 손실, 자동 오늘 이월 |
| 미래로 미뤄도 불안하다 | 잊을까 봐 계속 열어 봄 | 정한 시점의 재등장, 검색 가능 | 보관만 하고 다시 보여주지 않음 |
| ADHD 또는 실행 부담이 크다 | 입력, 선택, 기억의 부담 | 적은 필수 입력, 예측 가능한 위치, 회복 경로 | 진단 추정, 강한 알림을 일괄 적용 |

위 상황은 진단 분류가 아니다. 한 사람이 날짜마다 다른 어려움을 겪을 수 있다.

## 4. 사용자에게 약속할 것과 약속하지 않을 것

약속할 것은 입력 비용을 낮추고, 오늘 목록을 명시적으로 정하며, 보낸 날짜를 기억하고, 취소와 오류 복구를 제공하는 것이다.

약속하지 않을 것은 모든 일을 3분 안에 정리해 준다는 것, 위젯이나 알림이 항상 정확히 정시에 갱신된다는 것, 미룬 뒤 남은 일이 자동으로 최적의 우선순위라는 것이다. 사용자가 검토한 결과를 보존하는 제품이지 사용자의 책임과 판단을 대체하는 제품이 아니다.

## 5. 버전 범위

### 5.1 R0: 수직 흐름 검증

iPhone에서 입력, 날짜 정리, 오늘 목록, 완료, 되돌리기를 로컬 데이터로 연결한다. 실기기 위젯에서 오늘 / 내일, 주간 날짜 패널, 기타 딥링크를 검증한다. 실제 사용자 작업으로 사용할 수 있는 공개 버전은 아니다.

### 5.2 R1: 첫 사용 가능한 버전

| 영역 | 포함 범위 |
|---|---|
| 플랫폼 | iPhone, iPad 적응형 화면, 독립적인 Mac 네이티브 화면 |
| 입력 | 제목, 선택 메모, URL, 공유 텍스트, Siri / 단축어 텍스트 |
| 정리 | 일간 / 주간 정리, 5개 목적지, 주만 지정, 중간 종료, 다시 정리 |
| 실행 | 오늘 목록, 명시적 완료 / 완료 취소, 다시 배치 |
| 일정 | 일간 / 주간 날짜 보기, 선택적 기존 캘린더 읽기, 할 일 배치 |
| 데이터 | 로컬 저장, 선택적 iCloud 동기화, JSON 내보내기 / 복원 |
| 시스템 | App Intents, 대표 App Shortcuts, 중형 / 대형 위젯, 날짜 선택 딥링크 |
| 안전 | 실제 마감 분리, 단일 명령 멱등성, 충돌 기록, 개인정보 설정 |
| 알림 | 선택적 정리 알림, 사용자가 설정한 실제 마감 알림 |

Mac은 iPhone 위젯의 원격 표시만으로 지원했다고 보지 않는다. Mac 앱에서 입력, 정리, 일정 확인, 완료가 독립적으로 작동해야 한다.

### 5.3 R1 이후

Apple Watch 독립 앱, 집중 세션과 Live Activity, AI 작업 분해, 이미지 OCR, 자연어 날짜 자동화, 루틴과 반복 작업, 자동 시간 배치, 외부 캘린더 쓰기 / 양방향 미리 알림 동기화, 다중 프로젝트 구조는 후속 후보다.

앞서 논의한 기능을 삭제한 것이 아니라, 미루기 중심 흐름을 검증하기 전에 복잡도를 늘리지 않기 위한 범위 구분이다. 확장 기능이 데이터 모델의 의미를 뒤집지 않도록 경계만 남긴다.

## 7. 비기능 요구사항

다음 수치는 제품 성능 목표이지 측정된 결과가 아니다. 기준 데이터는 열린 작업 10,000개, 변경 기록 100,000개, 선택 캘린더의 조회 범위 내 일정 2,000개다. 실제 장비와 빌드 종류를 QA 결과에 기록한다.

| ID | 요구 | 초기 목표 / 판단 기준 |
|---|---|---|
| NFR-001 | 데이터 안전 | 정상 반환된 명령은 앱 종료 후 복원. 잘못된 작업 변경 0건 |

## 8. 성공 판단

핵심 성공은 앱 사용 시간이나 미루기 횟수 증가가 아니다. 정리의 부담이 낮아지고, 오늘 목록이 사용자의 의도와 일치하며, 미뤄 둔 일을 계속 확인하지 않아도 된다고 느끼는지로 판단한다.

개인 사용 검증에서는 정리 능동 시간, 정리 후 의도 불일치, 잘못된 배치, 마감 누락, 앱을 며칠 쉬었다가 돌아왔을 때의 복구 가능성을 함께 본다. 세부 정의는 11 문서에 있다.

## 9. 명시적 비목표

협업 프로젝트 관리, 팀 배정, AI 자동 우선순위 확정, 모든 캘린더 일정 자동 수정, 작업 시간을 자동 추정해 빈칸을 채우기, ADHD 진단 / 치료, 하루 전체 상시 Live Activity, streak 기반 벌점, 강제 계정 가입은 R1 목표가 아니다.

## 10. 변경 관리

새 기능 요청은 어떤 FR을 충족하거나 수정하는지 명시한다. 5개 목적지의 뜻, 오늘 목록 조건, 마감 구분, 재등장 정책을 바꾸는 요청은 UI 수정이 아니라 도메인 변경으로 분류한다. 03, 04, 08을 함께 바꿔야 한다.
