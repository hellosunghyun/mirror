# 03. 도메인과 정리 규칙

버전 0.1 / 이 문서는 상태와 날짜 의미의 기준 문서다.  
관련: [데이터 계약](04_DATA_AND_COMMAND_CONTRACTS.md), [테스트](08_QA_AND_ACCEPTANCE.md)

## 1. 핵심 용어

| 용어 | 의미 |
|---|---|
| 작업 Task | 사용자가 끝내거나 처리하려는 항목 |
| 계획 Plan | 언제 할지 또는 언제 다시 결정할지에 대한 사용자 선택 |
| 실제 마감 Deadline | 놓치면 실제 결과가 있는 시한. 계획과 독립 |
| 오늘 목록 Today | 사용자가 오늘 날짜에 배치한 열린 작업 |
| 정리 Review | 작업의 목적지를 결정하는 한정된 흐름 |
| 검토 주 Review week | 계획 시간대에서 월요일~일요일의 명시적 날짜 범위 |
| 검토 주기 Review cycle | 같은 계획 날짜에 대한 기본 일간 또는 주간 정리 단위 |
| 정리 세션 Review session | 특정 기기의 한 번의 정리 진입과 카드 탐색 상태 |
| 카드 Card | 특정 작업 / 버전을 보여주며 한 번의 결정을 받는 입력 단위 |
| 미검토 Undecided | 이번 검토에서 아직 목적지를 결정하지 않은 상태 |
| 보관 Parked | 사용자 요청으로 정기 정리 대상에서 제외한 작업 |

`미검토`와 `오늘`은 Task.status 값이 아니다. status는 실행 결과 상태이며, 계획과 검토 상태는 별개다.

## 2. 계획 상태

```text
PlanTarget =
  unassigned
  day(localDate)
  week(startLocalDate, endExclusiveLocalDate)
  parked
```

새 배치 명령에서는 오늘 이전 day, 월요일이 아닌 주 시작, 7일이 아닌 주 범위, 이미 끝난 주로의 배치를 거부한다. 과거 날짜의 기존 기록은 유효한 이력이므로 읽기와 복원에서 삭제하지 않는다.

`today`, `tomorrow`, `thisWeek`, `nextWeek`를 그대로 저장하지 않는다. 입력 시점의 PlanningContext로 절대 날짜 / 주 범위로 변환하여 저장한다.

| 계획 | 오늘 목록 | 기본 검토 진입 조건 |
|---|---|---|
| unassigned | 미포함 | 아직 정하지 않았고 현재 검토에 처리되지 않았음 |
| day(D) | D가 오늘이면 포함 | D가 오늘이거나 지났고 검토 확인이 필요함 |
| week(W) | 미포함 | 현재 날짜가 W 안이거나 W가 지났고 검토 유예가 끝남 |
| parked | 미포함 | 사용자가 명시적으로 꺼내거나 마감 안내에서 접근 |

완료 / 휴지통 상태는 모든 기본 정리 큐와 오늘 목록에서 제외한다. 실제 마감 안내는 별도 조회다.

## 4. 시간 모델

### 4.1 PlanningContext

```text
planningDay: YYYY-MM-DD
planningTimeZoneID: IANA timezone ID
calendarIdentifier: gregorian
weekStart: monday
policyRevision: stable settings-version string
capturedAt: UTC instant
```

권고 기본은 최초 기기의 시간대이며, 이 사용자 환경에서는 Asia/Seoul이다. 이후 여행으로 기기 시간대가 바뀌어도 계획 시간대를 자동 변경하지 않는다. 화면에 계획 기준 시간대를 표시하고 사용자가 변경할 수 있다. 이 정책은 기기마다 오늘이 달라져 같은 목록이 뒤섞이는 것을 줄이기 위한 제안이다.

설정의 계획 시간대를 변경하면 현재 정리 세션을 무효화하고 알림을 재예약한다. 이미 저장한 `2026-10-06`은 그대로 10월 6일이다. 시각이 있는 실제 마감은 UTC 시각을 유지한다. 날짜만 있는 마감은 생성 시 보존한 마감 시간대를 유지하며, 전체 변환은 별도 사용자 동작이어야 한다.

### 4.2 날짜 연산

오늘은 계획 시간대의 달력 날짜다. 내일은 Calendar의 날짜 덧셈으로 구한다. `Date + 86400초`로 계산하지 않는다. 주간 범위는 [월요일 시작, 다음 월요일 시작)이며 화면에는 월요일~일요일을 표시한다.

2026-09-30 수요일 기준:

```text
오늘      2026-09-30
내일      2026-10-01
이번 주   [2026-09-28, 2026-10-05)
다음 주   [2026-10-05, 2026-10-12)
```

일요일의 내일은 다음 주 월요일이다. 이번 주 버튼은 일요일 하루가 남더라도 의미를 바꾸지 않는다. 주 번호만 저장하지 않는다. 연말의 주는 두 연도에 걸칠 수 있으므로 날짜 범위로 처리한다.

### 4.3 자정과 오래된 카드

위젯 카드에는 표시 당시 planningDay와 policyRevision을 넣는다. 버튼이 처리될 때 현재 기준과 비교한다. 날짜가 달라졌으면 상태 변경 없이 `staleContext`를 반환하고 새 카드를 요청한다.

이번 주 패널의 절대 날짜 버튼도 R1에서는 planningDay 또는 policyRevision이 달라지면 재확인한다. policyRevision은 설정 변경 때 바뀌며, 자정에는 planningDay 비교가 날짜 변경을 검출한다. 자정 이후 “오늘”을 눌렀는데 어제나 예상과 다른 날짜에 배치되는 위험을 막는 일관된 규칙이다. 정확한 자정에 앱 / 위젯이 반드시 깨어나야 올바르게 작동하는 설계를 금지한다.

## 5. 오늘 목록과 실제 마감

```text
Today(day) = tasks where
  status == open
  AND plan.kind == day
  AND plan.date == day
```

이전에 사용자가 금요일을 지정한 일은 금요일에 오늘 목록에 포함된다. 이는 사용자가 미리 지정한 날짜를 존중하는 것이지 미검토를 자동 오늘로 넣는 것이 아니다. 그날의 정리에서 다시 빼낼 수 있다.

기본 순서는 해당 날짜에 배치한 결정 순서와 taskID의 안정적 순서다. 미래의 Today에 도달해도 순서를 매번 무작위로 섞지 않는다. 실제 마감 임박은 배지와 별도 안내로 표시한다. 복잡한 AI 우선순위 점수는 R1에서 쓰지 않는다.

실제 마감 안내의 권고 기본 범위는 지난 마감과 오늘 / 다음 계획 날짜까지의 열린 작업이다. 알림 권한과 무관하게 앱 내부에서는 조회 가능하다. 계획을 미래로 보내거나 parked로 바꾸어도 실제 마감이 삭제되지 않는다.

## 6. 일간 검토 대상

### 6.1 대상 집합

열린 작업 중 아래 하나에 해당하고, 이미 현재 검토 주기에 확인된 동일 계획 버전이 아니어야 한다.

1. 아직 계획을 정하지 않은 항목.
2. 계획 날짜가 오늘이거나 지난 항목.
3. 계획 주가 현재 주이거나 지난 주이며 `reviewNotBefore <= today`인 날짜 미정 항목.

미래의 정확한 날짜, 미래 주, parked, 완료, 휴지통은 제외한다. 마감 안내 때문에 미래 항목을 상세로 여는 것은 가능하지만 자동 정리 큐에는 추가하지 않는다.

`reviewNotBefore`는 검토 요청 시점을 미루는 장치이며 실제 실행 날짜가 아니다. 주만 정하기를 누른 현재 주 작업은 다음 계획 날짜부터 다시 검토할 수 있다. 단순 카드 건너뛰기는 현재 세션 끝까지 유예하며 다음 일간 주기에는 다시 가능하다.

### 6.2 같은 날 재검토

현재 계획 버전에 대한 `ReviewDecision`을 남긴다. 같은 planRevision을 같은 일간 주기에서 다시 묻지 않는다. 사용자가 상세에서 날짜를 바꾸었으면 새로운 계획 버전이므로 직접 재정리할 수 있다.

수동 “오늘 다시 정리”는 이미 오늘로 정한 항목을 다시 검토하는 명시적 override다. 자동 위젯 갱신이나 새 항목 입력이 이 override를 흉내 내면 안 된다.

### 6.3 검토 주기의 식별과 종료

기본 cycleID는 `workspaceEpoch + policyRevision + planningDay`를 결합한 안정적인 키다. 같은 날짜의 일간 / 주간은 같은 주기를 사용하고 mode만 다르게 표시한다. 기기마다 UUID를 새로 발급해 같은 날의 결정을 중복 요청하지 않는다. 정책 변경은 새로운 policyRevision으로 현재 세션을 종료한다.

`오늘은 여기까지`는 해당 주기에 CloseReviewCycle 기록을 남긴다. 이미 확인한 계획 버전과 미검토 목록은 별도로 유지한다. 종료 기록이 동기화되면 다른 기기도 기본적으로 오늘 목록을 표시한다. 오프라인 기기에서는 이 사실을 아직 모를 수 있으므로 즉시 모든 기기가 전환된다고 약속하지 않는다.

권고는 주간 모드로 진입한 사실을 로컬 세션에 남기고, 사용자가 주간 검토를 명시적으로 종료할 때 `weeklyCoverageStartDate`를 close 기록에 남기는 것이다. 이것은 그 주의 모든 작업을 검토했다는 뜻이 아니라 주간 검토 기회를 한 번 가졌다는 뜻이다. 아무 결정 없이 나갔다면 `이어 정리` 경로를 유지하고 강제로 매일 주간 모드를 열지 않는다.

## 7. 주간 검토 대상

권고 기본은 월요일의 선택한 정리 시각이다. 사용자가 다른 요일을 정해도 버튼의 “이번 주”는 실제 현재 주다. 일요일 저녁이라고 이번 주를 다음 주로 조용히 바꾸지 않는다. 다음 주를 미리 정하고 싶으면 다음 주 버튼을 사용한다.

주간 큐는 미지정 항목, 지난 계획에서 남은 항목, 현재 주의 날짜 미정 항목, 아직 일간 확인이 필요한 오늘 항목을 합쳐 구성한다. 미래 정확 날짜와 미래 주는 원래 결정을 존중하여 제외한다.

주간 정리를 연 주기의 일간 기본 큐는 별도로 중복 생성하지 않는다. 하나의 검토 흐름과 하나의 정리 알림만 사용한다. 주간 도중 오늘 / 내일 / 정확 날짜를 고르면 일간 목적도 함께 충족한다. 주만 고르면 `reviewNotBefore`에 따라 다음 날부터 날짜를 정한다. 방금 “요일은 나중에”를 누른 항목을 같은 세션의 2차 단계에 즉시 다시 올리지 않는다.

주간 정리를 건너뛰었다면 다음 첫 정리에서 “이번 주도 함께 정리”를 제안할 수 있다. 여러 주를 사용하지 않았더라도 지나간 주 수만큼 검토 세션을 생성하지 않는다.

## 8. 큐 순서와 진행

기본 정렬은 다음과 같다.

```text
1. 이미 지난 실제 마감
2. 오늘 / 가까운 실제 마감
3. 지난 실행 계획
4. 오늘 계획
5. 현재 주 날짜 미정
6. 미지정 항목 (생성일 오래된 것부터)
동순위는 생성일, taskID로 안정적으로 정렬
```

위 순서는 사용성 검증 전 권고안이다. deadline이 없는 일의 중요도를 낮다고 판단한 것이 아니다. 오래된 미지정 항목이 계속 굶지 않도록 기본은 FIFO다.

진입 시 대상 작업 ID 목록과 계획 버전을 세션에 기록한다. 처음부터 대량의 작업 내용을 모두 메모리에 올리지 않고 페이지 단위로 읽는다. 현재 카드는 제목 / 마감 / 상태 변경 이벤트를 반영하되 새로운 작업을 카드 앞에 끼워 넣지 않는다.

큐에 새 작업이 들어오면 자동 처리 중간에 순서를 흔들지 않고 “새로 넣은 일도 정리”를 종료 화면에 제공한다. 실제 마감 안내는 별도이므로 긴급한 마감이 기존 큐 뒤에 숨는 일을 줄인다.

다른 표면에서 완료 / 삭제 / 미래 배치된 항목은 다음 카드를 만들 때 건너뛴다. 현재 표시 중인 항목이 변경됐다면 stale 화면으로 전환한다. 카드 ID를 다른 작업에 재사용하지 않는다.

## 9. 목적지별 결과

| 입력 | 저장 결과 | 검토 확인 |
|---|---|---|
| 오늘 | day(today) | 현재 일간 / 주간 주기에 이 계획 버전 확인 |
| 내일 | day(tomorrow) | 현재 큐에서 제거. 내일 도달 시 Today 가능 |
| 이번 주 → 날짜 | day(selectedDate) | 현재 큐에서 제거 |
| 이번 주 → 요일 나중 | week(currentWeek) | 내일부터 검토 가능. Today 아님 |
| 다음 주 → 날짜 | day(selectedDate) | 해당 날짜 전 제외 |
| 다음 주 → 요일 나중 | week(nextWeek) | 해당 주 시작부터 검토 가능. 월요일 Today 아님 |
| 기타 → 날짜 | day(selectedDate) | 해당 날짜 전 제외 |
| 당분간 보관 | parked | 정기 검토 제외. 상세 / 검색으로 복귀 |
| 이번엔 넘기기 | plan 변경 없음 | 현재 세션에서만 순서 뒤로, 같은 세션 1회만 재제시 |
| 오늘은 여기까지 | plan 변경 없음 | 세션 종료, 미검토 보존 |

`이번엔 넘기기`는 앱의 보조 메뉴에서 제공한다. 위젯 5개 버튼에는 포함하지 않는다. 같은 항목을 무한 순환시키지 않도록 한 세션에서 다시 넘기면 종료 때까지 보류한다.

## 10. 마감 이후 배치 확인

정확한 날짜를 고를 때 선택 날짜가 실제 마감의 계획 시간대 환산 날짜보다 늦다면 확인을 요구한다. 같은 날짜에 시간 마감이 있다는 이유만으로 하루 배치를 무조건 금지하지 않는다. “오늘 15시 마감”을 표시한다.

주만 지정할 때 주 시작이 마감 이후라면 확인한다. 마감이 주 내부에 있으면 “화요일 마감, 날짜는 아직 정하지 않음”을 표시하되 날짜를 임의 결정하지 않는다.

확인은 `taskID + deadlineRevision + targetPlan`에 바인딩한다. 확인 사이 마감이나 대상이 바뀌면 확인을 재요청한다. `acknowledged=true`를 모든 미래 변경에 재사용하지 않는다.

위젯에서 복잡한 확인을 안정적으로 표시하지 못하면 작업을 변경하지 않고 앱의 동일 확인 화면으로 연결한다. 이때 원래 작업 ID를 유지한다.

## 11. 완료, 다시 열기, 보관, 삭제

완료는 status를 completed로 바꾸고 계획 / 마감 기록은 보존한다. 완료 날짜는 UTC timestamp다. 완료 취소는 상태만 open으로 되돌리며 이전 계획을 보존한다. 이전 계획이 지났으면 정리 대상이고 오늘로 자동 이동하지 않는다.

parked는 status가 open인 작업의 계획 목적지다. 휴지통은 삭제 상태이며 완료와 다르다. 휴지통 복구는 명시적 최신 삭제 사건을 참조해야 한다. 오래된 날짜 변경이나 완료 취소가 삭제를 우회하여 작업을 부활시키면 안 된다.

R1은 휴지통 자동 비우기를 하지 않는 권고안이다. 개별 작업의 이력까지 지우는 선택 삭제는 후속 범위이며, 현재 기기 데이터 삭제와 개인 공간 전체 삭제를 구분해 제공한다. 복구 가능한 휴지통 이동을 영구 삭제라고 표시하지 않는다. 구체적인 개인정보 삭제와 출시 게이트는 07 문서가 기준이다.

## 12. 의사코드

아래는 도메인 설명용이며 컴파일되는 Swift API가 아니다.

```text
isToday(task, ctx):
  return task.status == open
     and task.plan == day(ctx.planningDay)

isReviewCandidate(task, ctx, cycle, mode):
  if task.status != open: return false
  if task.plan == parked: return false
  if mode == automatic and cycle.closed: return false
  if task.reviewNotBefore != nil and task.reviewNotBefore > ctx.planningDay:
    return false
  if mode != manualTodayOverride and cycle.acknowledges(task.id, task.planRevision):
    return false
  match task.plan:
    unassigned: return true
    day(D): return D <= ctx.planningDay
    week(S, E): return S <= ctx.planningDay
    parked: return false

applyCardDecision(input):
  acquire device process-safe write gate
  load durable receipt by input.decisionToken
  if receipt exists: return same receipt or alreadyDecided
  validate current planning context
  validate exact task and version shown on card
  validate target and deadline acknowledgment
  append one immutable command record
  rebuild affected local projection
  record receipt and review acknowledgment
  invalidate widget snapshot
  return locallyCommitted
```

`manualTodayOverride`는 먼저 후보 집합을 오늘에 배치한 작업으로 한정한 뒤 acknowledgment를 건너뛴다. 미래 날짜나 보관 항목을 전부 다시 꺼내는 모드가 아니다. 중간 종료 후 사용자가 명시적으로 `정리 이어하기`를 누르면 closed 상태만 우회하며 이미 결정한 동일 계획 버전은 다시 묻지 않는다. 위 의사코드의 mode는 automatic / manualResume / manualTodayOverride로 구분한다.

완료된 동일 명령에 대한 재시도는 날짜가 바뀐 뒤에도 기존 결과를 반환한다. 그래서 중복 영수증 확인이 날짜 검증보다 먼저다. 아직 처리되지 않은 오래된 카드만 staleContext로 거부한다.

## 13. 예시

9월 30일 수요일에 “메일 보내기”를 10월 2일 금요일로 보낸다. 목요일 일간 정리에 나오지 않는다. 금요일 Today에 나타나며 해당 날짜의 검토에서 다시 배치할 수 있다.

“포트폴리오 수정”을 다음 주의 요일 미정으로 보낸다. 10월 5일 월요일에 검토 후보가 되지만 Today에는 없다. 사용자가 월요일을 누르거나 상세에서 그 날짜를 정해야 Today에 들어간다.

수요일에 10개 중 6개만 판단하고 종료했다. 그중 2개를 오늘에 남겼다면 오늘 목록은 원래 오늘 항목을 포함해 명시적으로 배치된 것만 보여준다. 나머지 미검토 4개가 자동으로 합쳐지지 않는다.
