# 08. QA와 수용 기준

버전 0.1 / 아래 항목은 실행할 테스트 명세이며 앱 테스트 결과가 아니다.

## 1. 테스트 계층

도메인 단위 테스트는 고정 Clock, PlanningContext와 동일 fixture로 실행한다. 영속화 테스트는 실제 Core Data SQLite store에서 저장 / 복구를 검사한다. 프로세스 경계 테스트는 앱과 확장에서 같은 카드에 동시에 명령을 보낸다. UI 테스트와 실기기 시스템 테스트는 위젯, Siri, 잠금, 권한, CloudKit을 다룬다.

순수 함수 통과만으로 WidgetKit과 iCloud의 동작을 검증했다고 판단하지 않는다. 모든 결과에 빌드 번호, OS, 기기, 계정 환경, 실행 일시, 증거를 남긴다.

## 2. 공통 테스트 데이터

기본 날짜는 2026-09-30 수요일, 계획 시간대는 Asia/Seoul이다. 다음 주는 2026-10-05부터 10-11까지다. 날짜 경계, 윤년, DST는 별도 벡터를 사용한다. 원문 제목에는 한글 조합형 / 이모지 / 긴 URL / 줄바꿈을 포함한다.

## 4. 추가 속성 기반 테스트

같은 원본 기록 집합을 순서만 바꿔 reducer에 적용해 최종 상태가 같은지 검사한다. 같은 event를 여러 번 넣어도 상태와 처리 건수가 같아야 한다. plan-only 명령을 임의로 생성하여 deadline이 변하지 않는지 검사한다. status가 completed / deleted인 상태에서 plan 기록을 추가해 status가 되돌아가지 않는지 검사한다.

현재 주의 모든 요일, 연말 주, 윤년, DST 전환, 시간대 변경을 생성하여 달력 날짜와 주간 범위가 올바른지 확인한다. 실제 앱의 Swift 구현을 `fixtures/domain-cases.json`의 기대값에 연결한다.

| Mac 앱 | 메뉴 / 키보드 / 다중 열, 독립 저장소 |

| iCloud 2기기 | offline 변경, 계정 전환, 전체 삭제 |

## 6. 장애 주입 위치

원본 저장 전, 원본 저장 후 투영 전, 투영 후 receipt 전, receipt 후 snapshot 전, snapshot 후 reload 전에서 각각 프로세스를 종료한다. 재시작과 같은 토큰 재시도에서 입력 손실과 중복 작업 생성이 없어야 한다.

네트워크 끊김, iCloud 용량 오류, 디스크 부족, 깨진 JSON, 보호 데이터 잠김, 잘못된 시간대, 계정 전환, 부모 record 지연을 재현한다. 데이터 불일치를 테스트하기 위해 실제 사용자 원본을 삭제하지 않고 별도 fixture 계정을 쓴다.

## 7. 출시 차단 결함

잘못된 taskID 변경, 정상 반환한 입력 유실, 자동 실제 마감 변경, 미검토 Today 유입, 삭제된 항목의 의도치 않은 부활, 계정 데이터 혼합, 민감 원문 로그 유출, 전체 삭제 의미의 허위 표시는 발생 빈도와 무관하게 차단이다.

기능 미지원은 명시적인 fallback이 있고 핵심 계약을 유지할 때만 허용한다. 위젯 성능 목표 미달은 실제 수치를 기록하고 G-WIDGET 판단을 거쳐야 한다.
