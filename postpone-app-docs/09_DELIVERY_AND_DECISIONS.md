# 09. 구현 계획, 결정 기록과 미결정 사항

버전 0.1 / 실행 가능한 작업 분해. 일정과 담당자 이름은 미정이다.

## 1. 구현 순서

```text
D-01 문서 / SDK 기준 고정
  → D-02 날짜 / PlanTarget
  → D-03 도메인 명령과 리듀서
  → D-04 원본 저장 / 투영 / 복구
  → D-05 카드 토큰 / 프로세스 게이트
  → D-06 iPhone 수직 흐름
  → D-07 App Intents
  → D-08 위젯 검증
  → D-09 주간 정리 / 종료 / Undo
  → D-10 동기화 / 충돌
  → D-11 Mac / iPad
  → D-12 캘린더 / 알림
  → D-13 개인정보 / 데이터 이동
  → D-14 접근성 / 성능 / 릴리스
```

실제 위젯의 주간 날짜 전환이 제품 UX에 큰 영향을 주므로 아름다운 전체 UI를 먼저 만들지 않고 위젯 수직 흐름을 빠르게 시험한다. 동기화도 출시 직전에 붙이는 부가 기능으로 취급하지 않는다.

## 3. 검증 게이트

### G-WIDGET. 5개 목적지의 실제 사용성

실제 중형 / 대형 위젯에서 카드 30개를 연속으로 정리한다. 오늘 / 내일, 주 패널 열기, 날짜 확정, 뒤로, 기타 앱 진입, Undo, 두 위젯 동시 사용, 앱 강제 종료를 포함한다.

측정은 사용자 탭부터 새 카드가 보이는 시점까지다. 저장 p95와 화면 갱신 p95를 따로 기록한다. 버벅임을 네트워크 탓으로만 돌리지 않고 snapshot 생성 / 저장 / OS reload를 나눠 본다.

실패 시 fallback은 주간 / 기타를 해당 앱 선택 화면에서 이어가는 것이다. 사용자 요청의 핵심이므로 이 fallback을 조용히 적용하지 않고 기대 UX와 차이를 ADR에 남긴다.

### G-SYNC. 두 기기의 같은 결론

두 실제 기기에서 오프라인으로 상충된 날짜, 완료, 삭제를 입력한다. 재연결 후 동일 operation 집합이 같은 projection을 만드는지 확인한다. 변경 기록이 유실되거나 계정 A 데이터가 B에 나타나면 출시 차단이다.

자동 미러링의 단순 샘플 성공만으로 통과시키지 않는다. extension 쓰기, 앱 종료, 원본 / 투영 사이 crash, 데이터 중복도 포함한다.

### G-DELETE. 데이터 삭제의 범위와 복귀

개인 공간 전체 삭제 후 오프라인 기기 재연결, 앱 재설치, 기존 export import를 나눠 시험한다. 의도하지 않은 데이터 재등장이 있으면 “완전 삭제” UI와 공개 출시를 차단한다. 사용자가 명시적으로 예전 export를 복원하는 것은 별도 동의 흐름이다.

### G-UX. 3분 약속의 의미

사용자가 미검토를 Today로 오해하지 않고, 주만 정한 일을 월요일 확정으로 오해하지 않는지 확인한다. 정리를 마친 후 실제 일을 시작하기보다 계속 날짜만 바꾸는 현상이 있으면 범위를 더 늘리기 전에 기본 흐름을 수정한다.

## 4. ADR

| ID | 결정 | 상태 | 이유 / 대안 |
|---|---|---|---|
| ADR-001 | 미루기 / 재결정 최소화 중심 | 사용자 방향 | 일반 프로젝트 기능 중심보다 현재 요청에 부합 |
| ADR-002 | plan과 deadline 분리 | 권고 명세 | 가짜 마감, 자동 이월, 일정 변경 혼동 방지 |
| ADR-003 | 주는 날짜 범위, Today는 명시적 day | 권고 명세 | 다음 주 월요일 자동 과부하 방지 |
| ADR-004 | Core Data + 불변 명령 기록 + 로컬 투영 | 기술 제안, G-SYNC 필요 | 단순 Task 직접 미러링보다 충돌 / Undo 명확. 구현 비용 증가 |
| ADR-005 | App Intents는 공통 서비스 어댑터 | 권고 명세 | 앱과 시스템에서 서로 다른 정책을 만들지 않음 |
| ADR-006 | 위젯 패널은 로컬 presentation과 timeline | 검증 필요 | 일반 앱 @State UI로 가정하지 않음 |
| ADR-007 | 계획 시간대 고정, 사용자 변경 | 권고 명세 | 기기 / 여행으로 날짜가 흔들리는 문제 감소 |
| ADR-008 | 정리 알림 하루 하나, 주간이 대체 | 권고 명세 | 정리 시간을 추가 의무로 늘리지 않음 |
| ADR-009 | AI / 타이머 / Watch 독립 앱 후속 | 범위 제안 | 핵심 루프 검증 전 기능 팽창 방지 |
| ADR-010 | R1 캘린더 읽기만 | 범위 제안 | 외부 일정 손상과 양방향 충돌 최소화 |
| ADR-011 | 같은 설정 위젯은 같은 로컬 scope 공유 | 권고 명세 | 확인되지 않은 위젯 인스턴스 ID 가정 제거 |
| ADR-012 | 3분은 목표, 강제 제한 아님 | 권고 명세 | 미검토 자동 배치 / 시간 초과 실패 방지 |
| ADR-013 | 영구 삭제는 전체 공간부터, 개별 이력 삭제 후속 | 범위 제안, G-DELETE 필요 | 불변 기록에 남은 원문까지 정확히 다루기 위함 |

ADR-004를 바꾸어 SwiftData 자동 미러링 등 단순화 경로를 택할 수는 있다. 단, 같은 카드가 다음 작업을 바꾸지 않는 규칙과 오프라인 완료 / 삭제 안전성은 그대로 충족해야 한다. 저장 기술 변경을 이유로 제품 약속을 낮추지 않는다.

## 6. 구현 전 반드시 실험으로 해결할 항목

위젯의 반응성과 중형 레이아웃, 최신 API availability, iCloud 계정 변경과 purge 복구, Core Data 여러 프로세스의 원본 / projection 처리, 한국어 Siri 작업 선택은 추정으로 완료 처리할 수 없다.

반대로 제품명, 유료화, 프로젝트 / 태그의 최종 확장 방식은 핵심 수직 흐름 구현을 막지 않는다. 팀이 모든 선택을 확정할 때까지 개발을 미룰 필요가 없다.

## 7. Definition of Done

요구사항 ID와 QA ID가 연결되어 있고, 명령 계약과 오류가 구현되어 있으며, 앱 / 인텐트 / 위젯에서 동일 결과를 만든다. UI 성공은 원본 저장 이후다. offline / 날짜 경계 / 접근성 / 개인정보 테스트 결과가 첨부되어야 한다.

시뮬레이터에서 보인 것만으로 실기기 완료, 로컬 저장 성공만으로 동기화 완료, 번들 스키마 검사만으로 앱 테스트 완료라고 기록하지 않는다.

## 8. 개발자 / 코딩 에이전트 인수 지침

01, 03, 04, 06 순서로 읽고 현재 티켓의 범위만 구현한다. 날짜 의미를 바꾸는 편의 기능을 임의 추가하지 않는다. 원본을 삭제하는 migration, 자동 마감 이동, 미래 작업의 자동 Today 포함, 외부 서버 전송은 별도 ADR 없이는 하지 않는다.

완료 보고에는 바뀐 파일, 구현한 FR, 실행한 테스트와 미실행 테스트, 알려진 제한, 다음 의존성을 적는다. 문서의 예시 API나 가칭 식별자를 검증 없이 생산 코드에 복사하지 않는다.
